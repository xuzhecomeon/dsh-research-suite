# 选题、假说、标书、伦理：从「想做什么」到「能不能立项」

本域只有两种失败模式。

**第一种是用不存在的理由当理由。**「该方向具有重要意义」「尚未见报道」「首次提出」——这三句在评审眼里等于什么都没说，第三句一旦被查证就是硬伤。本域的查新能力把「我觉得新」换成「我能点名对比谁、差在哪一轴」，并且禁止在没有点名具体已发表论文的情况下判「放弃」。

**第二种是在不可行的想法上继续堆砌。**用户已经在写标书第三章，而核心主张还撑不住一条最基础的反对意见。本域的可行性能力是**唯一具备否决权的闸门**：它判 NO-GO 时，设计卡与标书卡都不许继续往前推。

两条边界顺手说清：本域**不做文献精读**（转 literature 域），**不做统计执行**（样本量、检验选择、建模一律交 stats 域，本域只把「要算什么、参数从哪来」钉死），**不做成稿写作与润色**（转 writing、polish）。

| 你的处境 | 调用 | 得到什么 |
|---|---|---|
| 不知道走哪张卡 | `research_capability(id='ideation.topic')` → 按返回的卡片与触发词对齐 | 六张卡：topic／novelty／question／design／feasibility／grant／ethics（以返回值清单为准） |
| 要按顺序做完一段 | `research_playbook(task='写标书')` | 任务的能力序列、每步判据与交接件 |
| 需要看某个技能原文的细节 | `research_kb_read(name='aris-grant-proposal')` | 一次最多 2 个，只在本协议点名某节时读 |
| 要判断一段文字够不够硬 | `research_gate(text='…')` | 机械项检查结果（编造数字、不可核措辞、占位缺失） |

## 一、本域任务判定树

判定顺序不可跳过：**先判「这是哪一类活」，再判「能不能做」，最后才判「怎么写」。**反过来的顺序（先写再说）是本域最常见的返工来源。

```
用户诉求
├─ 还是模糊方向／一堆材料／一个觉得不错但说不清的想法
│   ├─ 只有一句话，没有任何材料 ─────────→ ideation.topic（发散→收敛→缺口补位）
│   ├─ 已有数据／预实验／综述，想尽快开工 ─→ ideation.topic 的「材料反推」支线
│   └─ 已有一个候选，只想知道值不值得做 ──→ ideation.feasibility 的「一句话故事＋致命缺陷」
│
├─ 候选已定，问「有人做过吗／够不够新」
│   ├─ 学术口径 ──────────────────────────→ ideation.novelty（三档裁决）
│   ├─ 专利／成果转化口径 ────────────────→ ideation.novelty 的专利分流支线（不得用学术口径代替）
│   └─ 目标只是写开题报告的「研究现状」 ──→ ideation.novelty 出差异表，正文交 writing
│
├─ 问题太大／太虚／想要机制解释
│   └────────────────────────────────────→ ideation.question（三层拆解＋三条竞争假说＋判决性预测）
│
├─ 想知道「这个设计撑不撑得住结论」「实验怎么排」
│   ├─ 临床／人群研究 ──→ ideation.design 的临床分支（PICO→设计类型→终点层级→随访窗口）
│   ├─ 基础实验 ────────→ ideation.design 的基础分支（实验1.1 式拆解＋筛选判据）
│   ├─ 社科实验／调查 ──→ ideation.design 的实验分支（RCT／析因／集群／审计／阶梯楔形／SMART）
│   └─ 计算／建模 ──────→ ideation.design 的计算分支（claim 类型、语料与切分、预定指标）
│
├─ 要钱：写标书／基金申请书
│   ├─ 指南与评审表在手 ─→ ideation.grant（读评审表→搭链条→反推创新点→六席预审）
│   ├─ 指南未定 ─────────→ 先按通用链条搭骨架，并在文首标注「假设指南版本」
│   └─ 只是问「该投哪家」→ ideation.grant 的机构对照表，不做期刊匹配（转 format 域）
│
└─ 涉及人、动物、敏感数据，或要注册
    ├─ 人（含问卷／访谈／病历）────→ ideation.ethics（批号＋知情同意＋脱敏三件套）
    ├─ 动物 ───────────────────────→ ideation.ethics 的动物分支（批号＋3R＋麻醉与安乐死）
    ├─ 仅公开二手数据 ─────────────→ ideation.ethics 的豁免分支（仍要写声明段）
    └─ 要不要预注册 ───────────────→ ideation.ethics 的三档判定（必须／建议／豁免）
```

三条**跨卡顺序**必须遵守：

1. **feasibility 在 design 与 grant 之前**，且是唯一的否决位。NO-GO 之后不许进设计卡与标书卡；若用户坚持，先把裁决降级理由写清楚，再按「改后可行」走。
2. **novelty 在 question 之前**：核心 claim 已被覆盖时，继续拆假说是浪费——先裁决，再拆问题。
3. **ethics 在数据收集设计之前**：涉及人的研究若未定审查类型与同意方式，设计卡不得进入「如何收数据」这一段。

**本域不做、要转出的事**：

| 诉求 | 转给 | 交接什么 |
|---|---|---|
| 帮我读这十篇／做综述 | literature | 差异轴清单、近邻文献清单、检索式 |
| 样本量算一下／用什么检验 | stats | 设计参数、功效分析类型、效应量来源、α 与把握度 |
| 把这些写成论文正文 | writing | 问题卡、claim 链、设计表、标书骨架 |
| 画机制图／技术路线图 | figures | 图清单与要表达的因果链 |
| 看我这稿会不会被拒 | review | 问题卡与 claim 表（作为审稿人视角的输入） |

**必须停下问人、不许凭记忆回答的四类硬事实**：当年指南的限项与页数、经费金额与预算上限、伦理批号与注册号、机构行政口径（单位盖章、提交系统）。一律改写成「需用户核对的三项」＋占位。

## 二、融合 SOP

以下每张卡的步骤与能力卡的 `protocol` 一一对应，展开成可照做的动作，并给出取长补短的依据。**取长补短不是取平均**：每个决定都说明「拿谁的哪一层、丢掉谁的哪一层、为什么」。

### 2.1 选题发现与创新点提炼（ideation.topic）

**触发**：想不出选题、方向太泛、idea 太安全、不知道怎么提炼创新点。
**输入**：研究方向／关键词／一句模糊诉求；可选已有材料（数据、预实验、导师方向、时间与资源上限）。**产出**：`IDEA_REPORT.md`（候选表＋淘汰表＋入选三句 pitch＋最强反对）。

1. **定题位与处境**。先问清三件事：要解决的是谁的问题、手上有什么（数据／样本／设备／时间）、终点是发论文还是立项。从十个 lens 里**只选 2～3 个**——全用只会得到十个平庸答案。
2. **发散出量**。用选定 lens 生成 **10～20 个**候选；每个先写一句话方法（2～4 步大白话）与核心假说，**不许先起标题**（先起标题会把候选压成论文形状）。再补最小可行实验、贡献类型、风险等级、工作量四栏。
3. **结构化收敛**。五道 filter 逐个过，每道带一条 kill criterion：讲得清（两句模板填不满即杀）、问题优先（说不出谁受益即杀）、简洁性（复杂度换来的提升在噪声内即杀）、相关性（挑不出一个会反对的人即杀）、可行性（两周内做不出可判定的 pilot 即杀）。收敛到 **3～5 个**。
4. **结构缺口补位**。用五个结构缺口 lens 再扫一遍：方法能否从邻近领域迁移、两篇文献是否互相矛盾、有没有被当公理却没检验的假设、结论是否只在某规模区间成立、缺的是不是诊断性工作。有材料时从材料反推 5 个可实证问题，每条点名变量与测量方式。
5. **淘汰留痕与交接**。只按机械事实淘汰：预估算力超过一周、数据可证实不可得、与他人已有产出重复。**novelty 与 impact 仅作注记、不据此删除**——淘汰权归机械事实，新颖性归查新卡。每个入选题写一段最强反对意见，新颖性统一标「待 novelty 卡核验」。
6. **交付三件套**。候选一页速览表（含 pilot 与风险等级）、淘汰表（每条一句话理由）、入选 idea 卡（三句 pitch：问题／做法／为什么现在）。

**取长补短的证据**：`airs-brainstorming-research-ideas` 给了十个 lens 与五道 filter 各带 kill criterion，是唯一能防「发散失控」的结构，但它**完全不检索文献**，新颖性只到感觉层；`aris-idea-creator` 给六字段候选卡与结构缺口 lens，可执行性好但发散宽度窄。本 SOP 取前者的发散结构＋后者六字段的落地性，把「新颖性」整段摘出去交给 novelty 卡——两张卡的分工就落在这里：topic 只负责「值得做」，novelty 才负责「没人做过」。

### 2.2 查新与差异化定位（ideation.novelty）

**触发**：这个想法有人做过吗、创新点够不够、和已有工作比新在哪、专利有没有被占。
**输入**：一句话 claim；领域关键词与近邻论文（可选）；目标期刊或基金方向（用于界定检索范围）。**产出**：`NOVELTY_REPORT.md`（claim 表＋检索留痕＋近邻工作四轴表＋三档裁决）＋一句可核查的定位句。

1. **抽可核 claim**。压成一句「我们主张 X 在 Y 条件下优于／区别于 Z」，再拆 **4～6 个**技术或方法要素。每个要素必须是别人能对照检索的名词，不是「更准」「更鲁棒」这类形容词。
2. **落可核库检索**。至少两个库：**PubMed／Web of Science／CNKI／Google Scholar 任选二**，逐一写下检索式、检索日期、命中数。专利另走 **Google Patents／Espacenet**，记录 IPC／CPC 类号。近六个月单独扫一遍——最容易被抢的正是这一段。
3. **逐条比对差异轴**。对最近工作的每一条，按四轴写差异：问题不同／方法不同／证据更强／结论相反。每轴只写一句，且必须能被该文献的摘要或图表支持；**找不出差异就承认重叠**，不硬造。
4. **三档裁决**。PROCEED＝无高度重叠且差异轴站得住；CAUTION＝有 1～2 篇近邻但差异可辩护；**ABANDON＝存在直接覆盖核心 claim 的已发表工作，且必须点名（作者、年份、标题、出处）**。ABANDON 点不出具体论文即为越权，最高只能 CAUTION。
5. **定位句与开头写法**。写一句可直接进引言或立项依据的话：「已有工作 A 已解决 x，但未处理 y，我们的做法在 y 上给出 z」。句中不得出现首创、空白、领先等不可核词。
6. **交 literature 深读**。差异轴清单与近邻清单交给 literature 做精读与偏倚评价；本卡**不评价这些文献的方法质量**。结论写回 idea 卡。

**取长补短的证据**：`aris-novelty-check` 的裁决边界最硬（没点名论文不许判放弃、delta 要落到可核查句），但它只做早期闸门、不做影响力判断；`aris-prior-art-search` 给了专利口径（重叠风险 HIGH／MEDIUM／LOW、FTO 初评、过期专利仍是现有技术）与检索式模板。本 SOP 取前者的裁决纪律＋后者的专利分流，并明确一条纪律：**热度只进描述、不进裁决**——话题热不等于被占，也不等于没人做。

### 2.3 研究问题与竞争假说构建（ideation.question）

**触发**：问题太大／太虚、PICO 怎么拆、假说怎么写、假说之间怎么互斥。
**输入**：选题与一句话 claim；已知现象或预实验观察；相关文献（用于抽竞争解释）。**产出**：`HYPOTHESES.md`（问题卡＋PICO 拆解＋竞争假说表＋判决性预测表）。

1. **分层：现象、机制、预测**。先写观察到什么（现象层），再写可能的原因（机制层），最后写若该机制成立还应看到什么（预测层）。**三层不许混在一句话里**——混在一起的问题是后面无法设计排除性对照的总根源。
2. **已知与未知分区**。列三栏：已被证据支持的、互相矛盾的、完全无证据的。**矛盾栏优先**，它是竞争假说的天然来源；每栏至少两条并附文献锚点。
3. **建竞争假说**。至少三条：主假说、一个替代机制、**一个纯方法学解释**（测量误差、选择效应、回归到均值）。三条必须互斥——若两个假说对同一实验给出相同预测，它们其实是一个，合并。
4. **质量判定**。逐条过五问：可证伪吗、可测吗、具体吗、有机制吗、有边界条件吗；再套 FINER（可行／有趣／新颖／伦理／相关）。任一项不合格就**改写而不是降分放行**。
5. **定量预测与证伪条件**。每条假说写一条判决性预测：在什么条件下、看到什么方向的效应、幅度至少多大算支持；同时写「若看到什么就放弃该假说」。幅度拿不准写「量级待 pilot 定，判据为方向＋超过最小可检测效应」，并标「待 stats 校准」。
6. **出问题卡**。问题句＋PICO 或 PECO 拆解＋三条竞争假说＋判决性预测表＋证伪条件＋与设计卡的交接说明（哪些对照是必须有的）。

**取长补短的证据**：`hypothesis-generation` 强在「竞争假说必须彼此可区分」与八步流程，但它不判选题价值、也不给论文级文献定位；`scholar-idea` 给问题合法性质询与五维筛选，`scholar-lit-review-hypothesis` 给缺口推导与证据矩阵。本 SOP 取前者的假说机制纪律＋后两者的分区证据，把「文献怎么写」留到 writing——本卡只要求「每栏有锚点」，不要求写成综述。

### 2.4 研究设计与技术路线（ideation.design）

**触发**：研究设计怎么写、技术路线、对照组怎么设、实验怎么排、临床／基础实验怎么设计。
**输入**：问题卡与竞争假说表；可用资源（样本、设备、时间、经费上限）；研究类型。**产出**：`EXPERIMENT_PLAN.md`＋`EXPERIMENT_TRACKER.md`＋「待 stats 计算清单」。

1. **冻结 claim 三层**。写主 claim、支持它的三条子 claim、一条反 claim（要主动排除的解释）。每条子 claim 标注「需要哪类证据才算支持」。此后排实验只认这三条子 claim。
2. **选定设计范式**。按类型走决策树：RCT／调查实验（情境或析因）／集群随机／审计通信／阶梯楔形／SMART／计算社科／基础实验。选定后写「为什么不是另一个」一句话，并**声明多重比较策略**（哪些比较纳入家族、用什么校正）。
3. **变量字典与因果图**。每个变量四栏：名称、定义、测量工具与单位、数据来源。再画一张 DAG，标出处理、结果、混杂与对撞，明确哪些混杂靠**设计**控制、哪些靠**分析**调整（后者必须进 stats 交接清单）。
4. **主结果表先行**。先画最终要交付的主结果表：行是条件或组别，列是主要终点，基线行与对照行留空；再倒推需要哪些 run、每个 run 的输入与产出，排出执行顺序与依赖。**填不进任何一格、也不能改变审稿人对某条 claim 信念的实验，砍掉。**
5. **里程碑、预算与风险**。切成五段里程碑（每周或每两周一个可验收产出），给预算量级与外部依赖，每个高风险环节写备选方案；稳健性检验按清单预先列出（如 Oster delta、E-value、置换检验）。
6. **生物医学分支抽提**。临床研究按纳排、干预、终点（主要／次要）、随访窗口逐项抽提；基础研究按「实验1.1」式编号拆到子实验，写检测方法与「若…则进入下一步」的筛选判据，分子名可匿名化为基因A式标签，缺失参数写「待定」。
7. **交 stats 做样本量与功效**。写清需要哪种功效分析（标准／多层／集群／贝叶斯 assurance）、预期效应量来源、α 与把握度要求，连同设计参数一起移交 stats 域执行 R 计算。**本卡不写具体 n。**

**取长补短的证据**：`aris-experiment-plan` 的长处是「从 claim 反推实验块、每块必须写失败怎么解释」，能挡住凑数消融；`scholar-design` 的长处是设计决策树＋变量字典＋DAG＋稳健性清单，但它默认统计分析自己做完。本 SOP 取前者的实验块纪律＋后者的设计规范化，把功效计算整段切给 stats（本卡只留「参数从哪来」），因为功效计算一旦两边都做，数字必飘。

### 2.5 立项前的可行性与致命缺陷审计（ideation.feasibility）

**触发**：这个题能不能做、值不值得做、有什么致命问题、要不要换题。
**输入**：选题卡与问题卡；资源与时间约束；已有预实验。**产出**：`IDEA_ASSESSMENT.md`＋两周 pilot 最小验证清单。

1. **一句话故事与类型定位**。一句话讲完「问题—做法—贡献」，再判类型（新现象／新方法／新证据／新场景）。**类型决定审稿人用什么标准看你**，判错类型会让后面所有准备错位。
2. **八类致命缺陷审计**。逐类扫：数据拿不到、样本不可得、识别策略不成立、关键测量无效、伦理不可过、时间不够、能力缺口、结论无法证伪。每类写「有／无／不确定」；有则给补救方案。**最多只列两条最致命的**，其余进备注。
3. **生命周期与能力匹配**。判断该题处在哪个阶段（概念验证／单点实验／成体系研究），对照团队能力与时间预算：阶段高于能力就要么降阶段、要么补能力（合作者、缩范围），不允许「边做边学」式跳过。
4. **五维打分只认证据**。五维（重要性、新颖性、可行性、证据强度、影响面）各 1～5 分，**每分必须附证据锚点**：文献、预实验、资源盘点。无证据的维度标「未评」而不是给中间分（中间分是最常见的自嗨）。
5. **对抗式压测**。写一段 **200 词以内**的拒稿 memo，用最不友好的口径说清「为什么不值得发表」，再逐条判断哪些可补救、哪些是设计层面的死结。
6. **三档裁决与前三动作**。GO＝可直接进设计与标书；GO WITH FIXES＝列出必改项后再进；**NO-GO＝阻断**，必须给替代方向或降阶方案。裁决后跟三条「本周就能做完」的动作。

**取长补短的证据**：`idea-evaluator` 的八步里最值钱的是「先查致命缺陷再打分」与「无证据只能给中间分」的纪律，它天生偏个人决策；`aris-kill-argument` 给 200 词拒稿 memo 与逐点辩护的对抗格式，但它只做对抗、不给严重度分级。本 SOP 取前者的闸门顺序＋后者的 memo 格式，并把「生命周期匹配」独立成一步——它是标书阶段最常见的崩盘点，却常被两张源技能都当成软指标。

### 2.6 标书撰写与评审视角自检（ideation.grant）

**触发**：写标书、国自然／NSFC 面上／青年、NIH Specific Aims、NSF proposal、立项依据与创新点怎么写。
**输入**：选题、问题卡与设计；目标基金与当年度指南（评审表、页数限制）；前期数据与团队。**产出**：申报书正文（含占位符与待补清单）＋评审自检表＋目标—方法—交付物对应表。

1. **读指南与评审表**。先把当年指南的评审表、页数、章节顺序、必备附件抄成一张检查表；评审表里**每个维度写一句「本标书用哪一节回应」**。指南未定时在文首标注「假设版本」。
2. **搭链条骨架**。按链条排节：科学问题→假说→总目标→具体目标（2～4 条，可测、各有交付物）→研究内容→方法（与目标一一对应）→预期结果→创新点→可行性→风险与备选→工作基础→经费与进度。**每节只回答一个评审问题。**
3. **反推创新点**。每条写成三段：已有工作做到哪、本项目的差异在哪、差异带来的可检验收益是什么。禁止「首次／填补空白／国际领先」；确需用「首次」必须附检索证据与时间窗。
4. **未来时态与证据对齐**。全文用「将／拟」写未来工作；已完成的前期结果**只用于证明可行性**。每条承诺标证据等级：已有数据支持／已有方法验证／仅有文献依据。
5. **经费、进度与团队**。经费按科目写理由（**不写金额，金额一律占位**），进度按半年度排可验收里程碑，团队按「谁负责哪块」对应到具体目标，缺的人写「拟引进／合作」。
6. **六席预审与回改**。跑六席：清晰度与合规、内部一致性、意义与指南契合、设计与可行性、预算与团队、对抗式资助建议；汇总成必改／建议改两张表，**逐条回到对应章节改**，不采纳的要写理由。
7. **格式、附件与终检**。按指南核对页数、字号、图表数、参考文献格式、必备附件（伦理批件、数据管理计划、推荐信、单位盖章），列提交清单逐项打勾。

**取长补短的证据**：`aris-grant-proposal` 给了通用链条、叙事弧五问与「grant ≠ paper（论证未来工作）」的时态纪律，但没有当年指南与限项；`research-grants` 给了五机构对照（NSF 两条准则等权、NIH 五条准则打分、页数与模块预算）、十类组件与五类常见错误；`arf-review-grant` 给六席对抗式预审与「提交前必改」清单。本 SOP 取第一者的骨架与时态＋第二者的机构口径＋第三者的评审席，**金额、限项、指南版本一律留空**——这三样是最容易被编造、也最容易被形式审查抓住的地方。另：`research-grants` 里「每份标书必须放 AI 生成图」的强条款不采用，图件本身交 figures 域，本卡只出图清单。

### 2.7 伦理审查、知情同意与预注册（ideation.ethics）

**触发**：伦理审查怎么申请、知情同意书、IRB、动物实验伦理与 3R、数据脱敏、要不要预注册。
**输入**：研究设计与研究对象（人／动物／公开数据）；数据类型与敏感级别；目标期刊或基金的伦理要求。**产出**：伦理申请材料包＋稿件用声明段＋预注册文档或豁免声明＋待补占位清单。

1. **判审查类型**。三分类：涉及人的研究（知情同意＋伦理批件）、动物实验（IACUC 批件＋3R＋麻醉与安乐死方式）、纯公开二手数据（多数可申请豁免，但要写数据来源与使用条款）。**判档依据写进材料，不写「应该属于豁免」**。
2. **知情同意与特殊人群**。写清：研究目的、要做什么、时长与负担、风险与获益、数据如何使用与保存多久、可随时退出、联系方式。涉及弱势群体加监护人同意；涉及欺骗设计加事后说明。
3. **脱敏与数据安全**。先本地扫描敏感字段（姓名、身份证、电话、住址、病历号、单位），出脱敏规则表（保留什么、泛化到什么粒度、用什么占位符），再决定哪些数据可以进模型。**脱敏后另存匿名副本，绝不覆盖原始文件。**
4. **决定是否预注册**。三档：必须注册（确证性研究、注册报告、期刊要求）、建议注册（有明确主假设的实证研究）、可豁免（纯探索性）。注册则写清主次假设、样本量依据、主要终点与分析计划；**已看过数据的必须声明已查看范围**。
5. **声明段与材料包**。出四段可直接粘贴的声明：伦理审查（批号占位）、知情同意（方式与是否书面）、数据可得性（共享级别与获取条件）、利益冲突与 AI 使用披露（工具、用途、人工核查方式）。再附材料清单与待补项表。

**取长补短的证据**：`scholar-ethics` 的审查类型判定表、知情同意要素与稿件声明模板可直接抄结构，但它只覆盖常见情形、不替代本机构委员会；`scholar-open` 给预注册平台与「注册什么」的清单；`scholar-safety` 给本地扫描与数据最小化动作。本 SOP 取第一者的文书结构＋第二者的注册判定＋第三者的扫描动作，并加一条源技能都没有的纪律：**批号、注册号、经费号一律全角方括号占位，任何一项都不许留空后被默认填写**。

## 三、常见错误清单

1. **先写标题再想问题**。标题会锁死问题形状；正确顺序是一句话方法 → 再命名。
2. **把「没人做过」当新颖性**。没检出 ≠ 没有；写成「未检出」并附检索式与日期，不写「尚未见报道」。
3. **拿话题热度当裁决**。热门方向漏检概率最高，热度只进描述。
4. **放弃结论不点名论文**。「我觉得这个被人做过了」不可交付；ABANDON 必须给作者、年份、标题、出处。
5. **假说不可证伪**。「X 会更有效」没有方向、幅度与条件就是愿望；每条假说都要有「看到什么就放弃」。
6. **竞争假说同机制**。两条假说对同一实验给相同预测＝一条；必须有一条纯方法学解释兜底。
7. **用描述性研究代替机制检验**。没有竞争假说就无法设计排除性对照，事后数据无法区分机制。
8. **设计卡自己算样本量**。本域只交功效分析类型与参数来源；数字由 stats 域用 R 算，口径不一致会直接导致设计自相矛盾。
9. **实验按文献范式铺满**。资源受限时冒进会让三条证据都软；先定主表、再砍不进主表的 run。
10. **用默认参数填补缺失方法细节**。细胞系、剂量、时间点、随访窗口缺失一律写「待定」，默认值是最隐蔽的编造源。
11. **可行性卡打中间分**。无证据维度标「未评」，不写 3 分；中间分等于用分数掩盖没查。
12. **NO-GO 之后继续写标书**。可行性是唯一否决位；跳过它，后面所有章节都在为一个站不住的主张做论证。
13. **标书用完成时写未做的事**。允许写风险，不允许把未验证写成已验证；一旦被识破，全篇可信度归零。
14. **创新点写成形容词**。「首次／填补空白／重大意义」不可核查；改成「相对 A 的哪一轴差异，带来什么可观测收益」。
15. **目标与方法错位**。具体目标没有对应方法模块＝悬空目标；评审第一眼就看这一段。
16. **伦理留白**。批号、同意方式、脱敏方案缺一项即不得交付；空白会被下游当成「无需填」。
17. **已看数据仍写成从未看过**。预注册时隐瞒已查看数据，会被判为事后假设，比诚实声明更伤可信度。
18. **编造任何具体数字**。基金名、批号、影响因子、审稿周期、经费金额、样本量：缺就占位，并在末尾附待补表。

## 四、交付前自检

交付任何一件产物前，逐条过下面这张表；每条都能被人工或脚本在三十秒内判定。

| # | 检查项 | 判据 |
|---|---|---|
| 1 | 候选量 | 候选不少于 10 个，每个有一句话方法；收敛后 3～5 个 |
| 2 | 淘汰留痕 | 淘汰表逐条有机械理由，且没有一条写「不够新」 |
| 3 | 查新留痕 | 每条 claim 能追到检索式、库名、日期、命中数；近邻表不少于 5 条且逐条写了四轴差异 |
| 4 | 裁决合规 | 无点名的 ABANDON 视为越权；离线或库不可用时裁决最高 CAUTION 并在报告中写明缺口 |
| 5 | 假说完备 | 每条假说有判决性预测与证伪条件；竞争假说不少于三条且含一条方法学解释 |
| 6 | FINER | 五项逐项有结论，无「待定」 |
| 7 | 设计对齐 | 每个子 claim 有对应方法，方向一一对应无悬空；主结果表行列在开工前已定 |
| 8 | 变量字典 | 每个变量有测量工具与单位，无空白栏；DAG 标出混杂与对撞 |
| 9 | 样本量 | 全文无凭空出现的 n，只写「待 stats 计算」与参数来源 |
| 10 | 缺陷审计 | 致命缺陷表覆盖八类，每类有明确结论；200 词拒稿 memo 已完成 |
| 11 | 裁决落地 | NO-GO 附替代方向；三档裁决后跟三条本周可完成动作 |
| 12 | 标书链条 | 目标—方法—交付物三列无悬空行；每条创新点能指到具体对比对象 |
| 13 | 时态与证据 | 标书全文未来时态；每条承诺有证据等级标注 |
| 14 | 伦理四要素 | 审查类型、批号占位、知情同意方式、脱敏方案齐全；动物加 3R 与安乐死 |
| 15 | 预注册 | 三档判定有理由，含「已查看数据范围」声明 |
| 16 | 无编造 | 全文扫描金额、批号、影响因子、样本量、审稿周期：一律占位或「待定」 |
| 17 | 无空话 | 全文无「具有重要意义／尚未见报道／填补空白／国内外首创」 |

机械可跑的两条：

```bash
node scripts/verify-capabilities.mjs ideation     # 包结构自检，须 0 errors
node scripts/verify-ledger.mjs ideation           # 源技能覆盖自检，须 0 errors
```

占位规范：未定硬事实统一写成【机构名】【伦理批号】【申报年度指南】【注册平台与注册号】这类全角方括号占位，并在交付物末尾附「待用户补全」表，写明缺什么、去哪拿、填进哪一段。
