# 投稿格式与参考文献（research-format）

本文件是 format 域 11 张能力卡的融合 SOP。每张卡在 `data/capabilities/format.json` 里有机器可读定义，本文件负责讲清「为什么这样排、做到什么程度算够」。

本域整体口径：**格式是可机械核查的，所以结论必须可核查**。三条红线——①参考文献必须真实可查，要素按 GB/T 7714-2015 齐全，缺的字段显式标注而绝不补写；②中文正文引用编号一律上标，参考文献表本身的序号不上标；③不造期刊数字，影响因子、分区、审稿周期、录用率一律不出现在交付里，技能库也没有任何技能能提供这类数据。

边界：literature 域交「要引什么」，本域管「怎么排」。文献检索、筛选、真伪判定、证据矩阵归 research-literature；统计重算归 research-stats；内容改写与润色归 research-polish。

## 一、本域任务判定树

按用户的抱怨原话分流，不要按用户可能不懂的术语分流。

| 用户说什么 | 实际要什么 | 走哪张卡 | 常见前置 |
| --- | --- | --- | --- |
| 「参考文献格式不对」「要 GB/T 7714」 | 按目标样式重排条目并体检字段 | format.ref-style | 先跑 format.cite-bind 或 doi 校验 |
| 「上标怎么弄」「编号乱了」「编号跳号」 | 正文标记与编号体系重建 | format.intext-cite | 先定 style 与顺序编码制 |
| 「EndNote 更新不了」「Zotero 刷不出来」 | 域代码与占位符桥接 | format.ref-bridge | 先确认用户装了什么 |
| 「能不能自动插引用」「哪句话该引谁」 | 主张与来源绑定、题录抓取 | format.cite-bind | 主张清单先定 |
| 「图表不合规」「图注要写什么」 | 三线表、题注、分辨率核查 | format.figtable | 抄刊约九项硬要求 |
| 「正文排得难看」「要转成 docx」 | 版式参数落实与成稿转换 | format.typeset | 参考文档或刊约 |
| 「PDF 读不出字」「要把图从 PDF 里提出来」 | PDF 摄取、页码校准、批量整理 | format.pdf-pipeline | 先探扫描件与 OCR |
| 「投稿前帮我体检一遍」 | 与参考文档逐项比对 + 机械检查 | format.doc-audit | 有参考 docx 更准 |
| 「投稿要准备哪些材料」 | 投稿包组装与就绪报告 | format.submission-package | 先有 format.journal-fit 结论 |
| 「投哪家合适」「字数超了吗」 | 期刊硬要求解析与候选匹配 | format.journal-fit | 无 IF 数据，只给匹配理由 |
| 「最终交什么格式」 | docx/PDF 交付与命名留档 | format.final-delivery | 前序卡全绿 |

判定树的三条硬规则：

1. **先定样式再动手**。样式不定就排版等于白干，作者截断、年份位置、卷期写法全会变。用户说不出样式时，去目标期刊投稿指南抄「参考文献」小节原文，抄不到就按正文语言所属体系默认（中文刊 GB/T 7714-2015 顺序编码制，西文刊 Vancouver 或 APA）。
2. **先体检再排版**。排一条假文献最贵：排版后再发现 DOI 打不开，全部返工。所以 ref-style 的第一步永远是最便宜的 DOI 可解析性检查，四态里只有 valid 才进排版。
3. **能机械判的必须机械判**。上标数、跳号、孤儿引用、半角标点、字数、图件 DPI、页数都要有数值口径和复核方式，不接受「看起来没问题」。

## 二、每卡融合 SOP

### 2.1 format.ref-style：参考文献表按样式成型

1. **定样式与口径**：确认目标样式（GB/T 7714-2015 顺序编码制、Vancouver、AMA、APA，或期刊自定义）；自定义样式必须抄原文句子，不凭印象套近似样式。混用时以正文语言所属体系为准。
2. **类型分流**：逐条判类型——有刊名卷期页且无出版者＝期刊；有学位类型与授予单位＝学位论文；有会议名与会址＝会议论文；有出版社与出版地＝专著；有网址与访问日期＝电子资源；判不准标「待确认」。
3. **排作者与年份**：作者 ≤3 人全列，>3 人列前 3 位后加「等」（中文）或「et al」（西文）；作者顺序不得改动；西文姓名姓前名后、名缩写不加点；年份位置随样式（GB/T 7714 在刊名后，APA 在作者后）。
4. **缺字段处置**：缺卷、期、页时写省略标记或「[卷号缺失]」，缺 DOI 标注「DOI 缺失」或省略；**绝对不许补写卷期页、猜 DOI、虚构出版社或会议名**。
5. **双向对账**：正文出现过的编号在文末必须存在，文末条目必须被正文引用；编号连续无跳号；同一文献不重复编号。
6. **交付与待核**：交付参考文献表 + 待核字段清单（哪些字段缺、缺在哪、建议去哪查）；多载体落位时按 docx、LaTeX、Markdown 各给一份可直接粘贴的纯文本。

GB/T 7714-2015 各类型条目模板（照此填空，不增不减）：

```text
[1] 王某某, 李某某, 张某某, 等. 题名[J]. 中华医学杂志, 2022, 102(5): 321-326. DOI: 10.3760/cma.j.cn112137-20210901-00001.
[2] Moore E E, Moore H B, Kornblith L Z, et al. Trauma-induced coagulopathy[J]. Nature Reviews Disease Primers, 2021, 7(1): 30. DOI: 10.1038/s41572-021-00264-3.
[3] 著者. 书名[M]. 3 版. 北京: 人民卫生出版社, 2020: 45-52.
[4] 著者. 题名[D]. 上海: 复旦大学, 2022.
[5] 著者. 题名[C]//论文集名. 北京: 中华医学会, 2019: 88-95.
[6] 著者. 题名[EB/OL]. (2023-05-10)[2026-11-06]. https://example.org/report.
[7] 著者. 题名[J/OL]. 刊名, 2023, 12(4): 55-61. (2023-04-01)[2026-11-06]. https://doi.org/10.xxxx/xxxxx.
```

要素清单（少一项就算不合格）：作者、题名、文献类型标识、刊名或出版者、年、卷(期)、起止页、DOI（有则必留，紧跟页码后，格式「DOI: 10.xxxx/xxxxx」）；英文刊名用 NLM 缩写，中文刊名用全称。

取长补短的证据：`paper-reference-formatter` 给了六步流程与「类型保守推断」规则，但只到条目成型，不做字段级核验；`qinyan-citation` 给了七种样式覆盖与缺失字段处理表，可它依赖先检索元数据；`nature-ref-verifier` 给字段级比对与三级严重度；`doi-validation` 给四态判定；`citation-manager` 给字段归一。本 SOP 把四者串成「先体检（DOI 四态）→ 再定样式 → 类型分流 → 排版 → 双向对账 → 待核清单」，前三份原文都只有其中一段。

### 2.2 format.intext-cite：正文引用与编号体系

1. **定体系与范围**：顺序编码制（按首次出现顺序编号）还是著者-出版年制（作者 + 年）；中文医学期刊多数是顺序编码制；体系一旦定下，全文不得混用。
2. **统一标记写法**：单篇 `[1]`、连续多篇 `[1-3]`、不连续多篇 `[1,4]`、带页码 `[1]5`（按目标刊要求，不自行发明）；同一处引用多篇时编号升序排列。
3. **按出现顺序重编**：从正文首个引用开始遍历全篇，遇到新文献才给新号；重编号后正文与文末表同时更新，不留中间态。
4. **上标与格式落实**：正文所有引用编号必须为上标，参考文献表序号不上标；中文语境下编号方括号用英文半角且置于标点前，整体仍按刊约；上标遗漏数为 0 才交付。
5. **双向核对**：正文编号集合与文末条目集合必须完全相等；文末序号连续、无跳号、无重号、无孤儿条目。
6. **交付与自查记录**：交付改好的正文 + 自查记录（上标数、编号总数、孤儿数、跳号数四项计数）。

检测口径（可机械执行）：遍历全文段落，统计「上标格式的引用编号出现次数」与「正文引用出现总次数」，两者必须相等；再统计文末表条目数与正文最大编号，两者必须相等。

取长补短的证据：`scholar-citation` 强在编号重建与审计模式（插入、审计、样式互转、全量重建都有），但它没有中文上标的硬口径；`chinese-medical-paper-writer` 恰好相反，它把「正文编号必须上标、参考文献表不适用」写成铁律并给了检测口径，却不给编号重建的算法。本 SOP 取前者的重建流程 + 后者的上标铁律与计数式，两段拼起来才既不乱号也不漏上标。

### 2.3 format.ref-bridge：文献管理软件桥接

1. **问清环境**：用户装了什么、版本、是否能联网刷新。有 Zotero 就走 Zotero 路线，有 EndNote 就走 EndNote 路线；两者都没有就走纯文本路线，**不要假定对方装了任何软件**。
2. **备料与归一**：把正文里的引用标记（如 `[PMID: 12345678]`）整理成清单，逐条拉题录；题名归一化必须统一（希腊字母转拉丁、智能引号转 ASCII、破折号转连字符、去方括号、去尾句点），否则占位符与书目对不上。
3. **选路线执行**：Zotero 路线生成原生域代码（引用域 + 文末书目域），用户点一次 Refresh 完成排版且样式可持久；EndNote 路线生成未格式化占位符 + 书目文件，用户在 Word 里点「Update Citations and Bibliography」。
4. **校验匹配率**：更新后统计未匹配条目数与匹配率；匹配率低于 100% 时逐条查原因（题名不一致、条目不存在、字段缺失），刷新缓存后重试。
5. **交付与操作说明**：交付 docx + 书目文件 + 三句操作说明（点哪里、什么时候点、样式如何换）。
6. **退路声明**：任何一步失败都要明说「本次未生成可刷新域代码，已给纯文本条目」，不隐瞒降级——隐瞒降级比降级本身更糟。

取长补短的证据：`format-references-zotero` 给域代码注入与 CSL 样式检索（覆盖九千多种样式，含中文期刊与学位论文模板），但要求本机装了 Zotero 桌面版并联网；`format-references-endnote` 给占位符与题名归一表，能离线生成文档但用户后续要手动更新；`pyzotero` 给批量备料；`bib-search-citation` 给完全不装软件时的本地书目退路。本 SOP 取 Zotero 的持久性 + EndNote 的离线可用 + 纯文本退路，做成三级降级链。

### 2.4 format.cite-bind：题录抓取与书目绑定

1. **定主张清单**：先把正文里需要引用支撑的句子逐条列出（每句一个主张），标出必须引、可引、不必引三类；不列清单直接插引用，必然出现「引了但不支撑」。
2. **取权威题录**：按标识符（DOI、PMID）取权威元数据，不按题名猜；同一文献多渠道取到时以出版商或 PubMed 记录为准；批量取数留日志。
3. **绑定与配平**：每条主张绑定 1～3 个来源；同一来源可在多处复用但只占一个编号；绑定后在正文标注位置，不改变原句意思。
4. **双路核字段**：一路从导出书目逐字抽取字段，一路重新取一次元数据，两边逐字段比差异；差异进待修清单，不以任一路为准强行合并。
5. **交付对照表**：交付「主张 → 来源（作者年 + DOI/PMID）→ 正文位置」三列对照表，附书目文件（.ris/.bib）与未解决条目清单。

取长补短的证据：`citation-management` 给了检索取数与交付形态，`pubmed-database` 给了按标识符精确取卷期页与作者的字段口径，`aris-citation-crosscheck` 给了「两路独立抽取再比差异」的防自证机制。本 SOP 取三者的取数、字段与双路核对，并补上「主张清单先行」这一步——没有它，抓来的题录再准也可能引错位置。

### 2.5 format.figtable：图表与题注规范核查

1. **抄刊约要求**：从目标刊作者须知抄九项硬要求——页数上限、字号字体、页边距、行距、引用样式、图表要求、文件格式、双盲匿名化、补充材料上限；图表数量上限与「图单独文件还是嵌入正文」也要抄。
2. **表格三线化**：只保留顶线、表头线、底线，无竖线；表题在表上方，表注在表下方；单位写在表头括注里；小数点按列对齐；空值留空不写 0；P 值写法统一（`P<0.001`，P 斜体）。
3. **图注要素齐备**：图序、图题、必要说明（缩写全称、单位、比例尺、染色方法、样本量、统计标注）、来源或改编声明；图题在图下方；正文必须按顺序提到每个图。
4. **技术规格核查**：分辨率线图 ≥300 dpi、照片类 ≥300 dpi、条图 ≥600 dpi 更稳；格式按刊约（TIFF/EPS/PDF，彩色用 RGB 或 CMYK）；宽度按单栏或双栏尺寸，不靠缩放硬凑；文件命名统一。
5. **编号与正文对应**：图表编号连续、无跳号；正文提及顺序与编号一致；删掉的图表要同步删正文提及。
6. **交付核查表**：交付「图表编号、类型、文件、分辨率、尺寸、题注要素齐全与否」六列核查表 + 待修项。

取长补短的证据：`venue-templates` 给了各刊九项硬要求与典型 DPI、页数阈值，但不管表格结构与题注写法；`chinese-medical-paper-writer` 给了三线表、题注位置、P 值写法的中文期刊口径；`scientific-visualization` 给分辨率与尺寸控制。本 SOP 取刊约要求 + 中文表格规范 + 图件技术参数，三层合并；三份原文任一单独用都会漏一层。

### 2.6 format.typeset：正文排版与成稿

1. **抄版式参数**：从参考文档或刊约抄下页面尺寸、页边距、正文字号与字体、行距、标题层级字号；参数写成表再动手。
2. **定结构与分节**：章节按语义分节，每节可独立起页；封面、目录、正文、附录各成节；页眉页脚只在需要时加，且必须绑到真实存在的标题级别，否则 Word 刷新会报错。
3. **生成语义 HTML**：用语义结构与样式变量生成中间 HTML；**禁用网格布局、禁用定义列表、禁用装饰性分隔线、禁用 span 模拟标签块**，多列一律用表格；字体、字号、颜色、对齐必须在每个块级元素上显式声明，不能依赖继承（转换器不做继承计算）。
4. **转换前门禁**：跑 HTML 质量门禁（结构、样式、图片、链接、可转换性五项），不过关就改 HTML 再转，不要带病转换。
5. **转换与回读**：一键转 docx 后回读校验页数与结构；转换结果的返回是结构化文本，必须按结构解析成败与插入位置，不能靠正则猜。
6. **成品修正与交付**：在 docx 上做成品级修改（页边距、页码、题注对齐），交付 docx + 版式参数表 + 已知差异说明。

取长补短的证据：`doc-typeset` 给七套垂类模板与「转 docx 的 HTML 禁忌」清单（最实用的一条是最关键的样式属性不能依赖继承），但它需要一道门禁才敢转；`html-review` 正好是这道门禁；`html-to-doc` 给转换与结构化结果判读；`docx` 给成品级修改。本 SOP 把「模板 → 门禁 → 转换 → 成品修正」串成流水线，缺任一段都会出散架文档。

### 2.7 format.pdf-pipeline：PDF 摄取与页面核对

1. **判用途定模式**：总结与问答用纯文本模式最快；核对版面、提取表格、看图用结构或图片模式；先定用途再选模式，不要一上来就全量转。
2. **先探能否读**：扫描件需要 OCR 引擎，本机没有引擎时必须如实报错，**不得把失败当空白页**；组件未就绪时按提示等待重试，不要另装替代工具。
3. **校准页码**：结构视图的页码从 0 起、Markdown 页注释与导出图片从 1 起，先核两页样本再批量引用页码。
4. **抽内容并标注**：抽取文字与表格时保留表头与单位；合并单元格在 CSV 里会丢跨度，需要保真时用结构化输出或截图核对。
5. **批量整理**：多份 PDF 先做完整性校验与哈希去重，再统一改名（第一作者 + 年 + 简短题名），处理报告留档。
6. **交付与限制说明**：交付提取结果 + 页码对照表 + 限制说明（哪些页是扫描件、哪些表未能保真）。

取长补短的证据：`workbuddy-pdf` 给了模式表、页码起点、退出码语义（组件未就绪与找不到命令要区别对待），但明确不支持生成或编辑 PDF；`pdfkit-py` 给页面级拆分合并与加密处理；`pdf-processing` 给批量校验、去重、改名与报告；`pdf` 给受损文件容错。本 SOP 取「读」的主干 + 「批处理」的工程化，并把「不得硬造 PDF」写成边界。

### 2.8 format.doc-audit：参考文档比对与投稿前体检

1. **定尺子**：有参考文档（目标刊已发表样张或期刊模板）就先抽取其语义结构与版式特征，作为比对基准；抽不出来要明说「本次未成功提取参考文档格式特征」，用刊约文本代替。
2. **机械检查**：跑三类可穷尽检查——拼写与术语一致性、交叉引用与编号完整性、无支撑主张（数字与结论缺来源）。
3. **版式比对**：按七维权重体检——排版规范、内容真实、可行性、内容真伪、AI 痕迹、学术规范、期刊适配；输出百分制评分与红黄绿分档，只诊断不开药方。
4. **硬问题排查**：单独排查图像复用、数据异常、统计量与样本量矛盾；结论只写「疑似」并给证据位置，不定性、不指控。
5. **引用与条目核对**：条目核对按批量分层——≤10 条逐条核，11～30 条精简核，>30 条重点核可疑条目 + 抽样并说明比例。
6. **待修表交付**：按优先级排序（致命 → 重要 → 提示），每条给位置、问题、改法方向；不给成稿。

取长补短的证据：`format-extract` 给参考文档结构抽取与质量检查，是「尺子」的来源；`arf-review-paper-checks` 给三类机械检查；`paper-ct-scan` 给七维权重与只诊断边界；`geng-academic-fraud-detector` 给硬问题排查但措辞需收敛；`reference-verification` 给抽样分层。本 SOP 取四家之长并按「尺子 → 机械 → 版式 → 硬问题 → 引用 → 排序」排出执行顺序，避免一上来就凭印象挑毛病。

### 2.9 format.submission-package：投稿包组装

1. **抄材料要求**：从刊约抄投稿材料清单与格式要求（是否要标题页单独文件、图表是否分文件、补充材料命名规则、文件格式与大小上限）。
2. **分版出稿**：出盲审版（去作者、单位、致谢、基金、可识别自引）与署名版两份；两版正文内容必须一致，只差署名信息。
3. **组补充材料**：补充表、补充图、代码与数据说明分开命名（S1、S2…），与正文引用一致；补充材料里也要有标题与说明。
4. **声明类文件**：作者贡献（CRediT 分类）、利益冲突（无也要写 none）、数据可得性、伦理批件号与知情同意、基金与致谢、预注册号、AI 使用声明。
5. **封面信**：五段——开场、研究贡献、与刊匹配理由、声明、结尾；信里每条主张必须能在稿件里找到对应证据，不得出现稿件里没有的数字；作者、单位、ORCID、伦理号抽不到就写占位。
6. **逐项对表并交付**：按清单逐项打勾（通过/不通过/不适用），交付投稿包目录 + 就绪报告；有不通过项就不算就绪。

投稿包清单（18 项，逐项打勾）：

```text
1  正文（盲审版）        10 数据可得性声明
2  正文（署名版）        11 伦理批件与知情同意
3  标题页（含单位）      12 预注册声明（如有）
4  摘要与关键词         13 作者贡献（CRediT）
5  图表分文件           14 补充材料与命名
6  图件源文件与分辨率    15 封面信
7  参考文献表           16 推荐与回避审稿人
8  基金与致谢           17 ORCID 与通讯信息
9  利益冲突声明         18 文件格式、命名与大小核查
```

取长补短的证据：`scholar-journal` 给了 17 项投稿前清单与就绪报告形态，是最完整的骨架；`chinese-medical-paper-writer` 给了中文刊的首页脚注与声明项（伦理号、基金、通信作者）；`cover-letter` 的 align-check 要求信里每条主张可回溯到稿件证据；`paper-ct-scan` 给「就绪与否」的兜底判断。本 SOP 取骨架 + 中文刊脚注 + 主张对齐，并补出「盲审版与署名版内容一致」这条常被忽略的核对项。

### 2.10 format.journal-fit：期刊要求解析与选刊

1. **解析硬要求**：把候选刊的作者须知拆成九项硬要求表（页数、字号、页边距、行距、引用样式、图表、文件格式、双盲、补充材料上限），逐项与稿件比对，标「已满足/需调整/不适用」。
2. **稿件自量**：统计正文字数（不含参考文献）、图数与表数、参考文献条数、摘要字数，四项与刊约比对，超出就要给压缩方案而不是硬交。
3. **候选与匹配**：候选刊按八维打分（范围匹配、方法匹配、理论或视角匹配、字数匹配、影响力预期、开放科学准备度、周期偏好、读者面），每维 1～5 分求和排序；打分要写理由，不写空分。
4. **转投阶梯**：给出 A→B→C 的转投顺序与理由；退稿后按阶梯走，不在同一层次反复试错。
5. **数据边界声明**：影响因子、分区、审稿周期、录用率**一律不写**——技能库没有这些数据，写了就是编造；只给匹配理由、硬要求对表与转投建议，需要这些数字时让用户去官方来源现查。
6. **交付选刊报告**：交付候选表（刊名、匹配维度分、硬要求差距、理由）+ 首选建议 + 需用户确认的项。

取长补短的证据：`scholar-journal` 给了八维评分与期刊阶梯，可直接落地；`venue-templates` 给了各刊九项硬要求与典型页数，可做硬指标校验；`cover-letter` 的 journal-fit 四子轴（范围、新颖性框架、证据密度、格式合规）可作为补充视角。本 SOP 取评分 + 硬要求 + 四子轴，并写死「不造期刊数字」的红线，把「没有数据就说明没有数据」变成硬要求。

### 2.11 format.final-delivery：终稿交付形态

1. **定格式与命名**：文字类交付优先 .docx（期刊要 .doc 就另存），需要固定版式或送审时才给 .pdf；命名统一为「刊名简写-稿号或日期-版本」，不用「最终版」「新建文档」这类名字。
2. **生成与回读**：生成后回读校验（段落数、标题层级、图表数量、页数），确认没有丢内容；中文语境标点全角、英文与数字半角、不要 Markdown 残留符号。
3. **LaTeX 稿编译**：LaTeX 项目按 xelatex → bibtex → xelatex 两遍的顺序编译；未定义引用与缺图逐条修，不接受「编译有几个警告但能出 PDF」。
4. **双格式一致性**：docx 与 PDF 两版必须一致（字数、图号、表号、参考文献条数、页数差异有解释）；不一致就以一种为基准重出另一种。
5. **交付与清单**：交付主文件 + 附带文件（图件源文件、补充材料、书目文件）+ 交付清单（含每份文件的用途）。
6. **版本与留档**：保留一份可编辑源文件与一份导出件，版本号写进文件名；覆盖用户原文件前先确认，默认不覆盖。

取长补短的证据：`docx` 给生成、批量样式修改与校验，是 docx 路线的主力；`latex-output` 给学校或期刊模板套用与编译顺序；`aris-paper-compile` 给编译报错逐条修到出 PDF；`html-to-doc` 作为兜底转换。本 SOP 取 docx 为主、LaTeX 为辅、HTML 转 docx 兜底的三级交付链，并要求双格式一致性核对——这一步原文都没写。

## 三、常见错误清单

1. **样式没定就排版**。改法：先抄刊约引用小节原文，再动手。
2. **补写缺失字段**。表现：卷期页看着「合理」但是编的。改法：缺就标缺，绝不补。
3. **参考文献表序号也上标**。改法：只有正文引用编号上标，文末表序号不上标。
4. **编号跳号或孤儿**。改法：正文与文末双向集合比对，四项计数归零。
5. **多篇合并写成 `[1][2][3]`**。改法：按刊约写 `[1-3]`，升序。
6. **假定用户装了 Zotero**。改法：先问，没有就给纯文本条目。
7. **转换器崩了就换工具硬做**。改法：按门禁改 HTML，或如实说明不支持。
8. **扫描 PDF 读不到就当空白**。改法：报 OCR 缺失，给用户选装或改交其它格式。
9. **页眉绑错标题级别**。改法：页眉引用的标题级别必须在正文真实存在且已套用。
10. **图注只写图题**。改法：缩写、单位、比例尺、统计标注、来源都要有。
11. **表用截图贴进去**。改法：表格必须是可编辑文本。
12. **投稿包只有正文**。改法：按 18 项清单逐项打勾。
13. **封面信吹稿件里没有的数字**。改法：每条主张回溯到稿件证据。
14. **选刊时编影响因子与审稿周期**。改法：一律不写，让用户去官方源查。
15. **docx 与 PDF 两版不一致**。改法：以一份为基准重出，交付前核对五项。

## 四、交付前自检

| 检查项 | 判据 | 怎么查 |
| --- | --- | --- |
| 条目要素齐全 | 每条都有作者、题名、类型标识、来源、年、卷(期)、页、DOI（有则必留） | 逐条过要素清单 |
| 无编造字段 | 凭空补出的卷期页条数 = 0 | 与权威记录比对 |
| 上标合规 | 正文编号全部上标，文献表序号 0 处上标 | 计数比对 |
| 编号自洽 | 跳号 = 0，孤儿条目 = 0，重号 = 0 | 集合比对 |
| 期刊数字为零 | 影响因子、分区、审稿周期、录用率出现次数 = 0 | 关键词清点 |
| 图表合规 | 三线表、图注要素齐、分辨率 ≥300 dpi、编号连续 | 核查表逐项 |
| 投稿包完整 | 18 项清单全部「通过」或「不适用」 | 逐项打勾 |
| 交付形态 | docx 为主、需要时 PDF，命名含版本 | 文件清单核对 |
| 标点合规 | 中文语境半角逗号、句号、括号、直引号 = 0 | 全文搜索 |
