# 自审、审稿、修回、回复信：把「投出去」推到「改到中」

本域只有两种失败模式。

**第一种是无法执行的评语。**「整体创新性不足」「论述有待加强」「建议补充相关文献」——作者看完不知道要改哪一句、补什么、改到什么程度。本域的硬规定是：**每条质疑必须写全「位置 + 问题 + 依据 + 建议」四件套，缺一项不计入结论**。位置精确到节、段、行、图号或表号；依据必须是原文引句或表内的数字，不能是印象。

**第二种是越界的审稿。**要求补一场全新实验、按审稿人个人偏好改理论框架、把「我没读过这条文献」当成缺陷。越界要求是审稿人被编辑退回重写、被作者投诉的头号原因，也会让真正重要的意见被稀释。

全域贯穿**审稿三问**，三问逐项作答、每条落到具体段落或图表：

1. **这个结论的数据支持得住吗？**——设计能否支撑因果、效应量与不确定区间是否给、多重比较是否校正、有没有选择性报告。
2. **和已有工作相比新在哪？**——能否点名最近的三篇，并说清差异落在哪一轴（问题／方法／证据／结论）。
3. **按目标期刊的读者，能读懂并复现吗？**——方法是否写到可复现、报告规范是否齐、图表是否自明。

边界先说清：本域**不做语言润色**（转 polish，本域只在报告里标「语言需打磨」并给例句位置），**不做统计重算**（重算与建模转 stats；本域负责指出统计缺陷并给出该重算什么），**不改稿**（除用户明确要求修回执行外，本域是审稿方与顾问方，不是编辑）。

| 你的处境 | 调用 | 得到什么 |
|---|---|---|
| 不知道走哪张卡 | `research_capability(id='review.presubmit')` → 按返回的触发词对齐 | 八张卡：presubmit／referee／report／audit／revise／rebuttal／appeal／selfcheck |
| 要按顺序做完一段 | `research_playbook(task='修回')` | 能力序列、每步判据与交接件 |
| 要看某技能原文的细节 | `research_kb_read(name='peer-review')` | 一次最多 2 个，只在本协议点名某节时读 |
| 要机械检查一段意见 | `research_gate(text='…')` | 四件套缺失、无可执行动作、编造数字、越界要求等命中项 |

## 一、本域任务判定树

判定顺序：**先问「我是哪一方」，再问「要不要判生死」，最后才动手写。**审稿方与作者方的语言与目标完全不同，混着写是本域最大的返工来源。

```
用户诉求
├─ 稿件还没投（我是作者，想投出去）
│   ├─ 只想知道会不会被秒拒 ──────────→ review.presubmit（主编三筛＋五维自查）
│   ├─ 想被狠挑一遍再改 ──────────────→ review.referee（配置卡＋五席＋两百字拒稿 memo）
│   ├─ 数字与主张对不上，想核一遍 ────→ review.audit（主张清单＋零上下文核验）
│   └─ 已改完，想确认这次可以投 ──────→ review.presubmit 的机械项 + review.selfcheck
│
├─ 稿件已投，结果回来了（我还是作者）
│   ├─ 拿到决定信与意见，要排改稿 ────→ review.revise（决定类型＋分诊＋范围控制）
│   ├─ 要写逐条回复信 ────────────────→ review.rebuttal（三道硬门＋四段式＋字数裁剪）
│   ├─ 直接被拒，要考虑申诉或转投 ────→ review.appeal（四型 triage＋七类根因＋期刊阶梯）
│   └─ 只想看「审稿人到底在说什么」 ──→ review.revise 的分诊表，不要直接动笔
│
└─ 我受邀审别人的稿（我是审稿方）
    ├─ 要给编辑一份正式意见 ──────────→ review.report（推荐等级＋两级问题＋保密评语）
    ├─ 自己已写完，想查是否可执行 ────→ review.selfcheck（六项打勾＋越界检查）
    ├─ 想先想清楚再动笔 ──────────────→ review.referee（五席预演，但**不得**把预演当正式意见）
    └─ 稿件只有预分析计划 ────────────→ review.referee 的 PAP 分支（六席计划预审）
```

四条**跨卡规则**必须遵守：

1. **先定生死，再谈治疗**。用户问「会不会被拒」时，先出决定等级与主要拒稿理由（presubmit／referee），不要直接给改稿清单；问他「怎么改」时才转 revise。
2. **核验先于修辞**。凡涉及数字与主张，audit 在前；报告写得再好，数字对不上就一通百通。
3. **预演不等于正式意见**。referee 的五席报告是作者侧的自查工具，**不得**原样当作给编辑的审稿意见；正式意见必须过 report 与 selfcheck。
4. **修回阶段禁止范围蔓延**。第二轮及以后不得引入未被要求的新分析、新引用、新论证——这是返修被拒的第一原因。

**本域不做、要转出的事**：

| 诉求 | 转给 | 交接什么 |
|---|---|---|
| 把这句改顺、去掉 AI 味 | polish | 意见清单里标注的语言问题位置 |
| 重跑统计、换模型、算功效 | stats | 要重算什么、原分析与原始数据在哪 |
| 重做图表、调分辨率与配色 | figures | 图号与问题（轴无单位、误差棒未定义、分辨率不足） |
| 排参考文献、投稿包格式 | format | 目标刊样式与不合格条目清单 |
| 整篇重写成稿 | writing | 审阅结论与结构性改写建议 |

## 二、融合 SOP

### 2.1 投稿前自审：主编预筛与五维自查（review.presubmit）

**触发**：投稿前自审、会不会被秒拒、desk reject 风险、格式合规自查。
**输入**：稿件全文或可读章节；目标期刊与文章类型；数据与代码可得性说明、图表源文件（可选）。**产出**：`presubmission-report.md`＋`must-fix-list.md`。

1. **定刊定位与投稿类型**。确认目标刊的范围声明、文章类型与字数上限，把核心主张压成一句话，比对是否落在该刊读者关心的范围内。**范围不符直接判红**，不再往下挑细节。
2. **主编三筛**。按「范围契合／贡献可信／有无致命缺陷」三问各写一行判断，各带一段原文依据。三问全过才进五维；任一不过先处理该问。
3. **五维自查**。宏观逻辑、写作细节、英文表达、排版格式、图件质量五维逐维过，每维只记问题不写评语，问题必须落到节号或行号。
4. **分节红旗取证**。摘要看主张是否超出结果；方法看随机化、盲法、纳排、软件版本与多重校正；结果看选择性报告与误用检验；讨论看是否把相关写成因果、是否忽略相反证据。每条红旗引原文一句。
5. **机械项核对**。图表编号与正文引用一一对应、参考文献按目标刊样式、上标编号与文末表双向对应、字数与页数是否超限、补充材料清单、利益冲突与数据可得性声明。**逐项给通过／不通过，不写「基本合规」**。
6. **分级与必改清单**。按 CRITICAL／MAJOR／MINOR 分三栏；**CRITICAL 命中即判「不宜投稿」并标明阻断项**；每条给可执行动作（改哪句、补哪个数、换成哪个表述）。

**取长补短的证据**：`pre-submission-reviewer` 的五维清单与严重度分级最贴近「作者自己能不能改」，但它不判生死；`paper-audit` 的闸门模式给了「只有 Critical 阻塞投稿」的明确规则与机械项清单；`arf-review-paper-light` 给贡献四档与识别策略外生性三问，几分钟就能出结论。本 SOP 取第一者的五维＋第三者的快筛口径＋第二者的阻断规则，把「三问＋五维」做成两张表而不是一段总评——合并成一段总评是这一卡最常见的退化。

### 2.2 审稿人视角深度质疑（review.referee）

**触发**：模拟审稿、审稿人视角、帮我找漏洞、对抗式评审、kill argument。
**输入**：稿件全文或核心章节；目标期刊与评审口径；上一轮意见（可选）。**产出**：`mock-review.md`＋`kill-argument.md`。

1. **生成评审人配置卡**。读出主学科与次学科、研究范式（实验／观察／计算／质性）、方法类型、成稿成熟度，据此生成四张配置卡（席位、专长、关注点、最可能的拒稿理由），**先给用户确认再开跑**。
2. **分节取证**。摘要、引言、方法、结果、讨论逐节过，每节至少一条「可被审稿人抓住」的点，写成位置、问题、依据、建议四项，依据必须是原文引句或表内数字。
3. **最强反驳**。换一个从未看过稿子的视角，用**两百字**写出最强拒稿理由：一句话说清如果被拒会因什么被拒，再列三条支撑。写完不要立刻自我反驳（自我反驳会把最强一击削平）。
4. **五席独立质疑**。期刊契合席、方法席、领域席、跨学科影响席、对抗席各写一份独立意见，各席**不得互相引用结论**，最后才汇总。
5. **证据质量定级**。对每条主结论标证据等级与偏倚风险：设计能否支持因果、有无混杂与选择偏倚、效应量与不确定区间是否给、多重比较是否校正。定级必须写理由。
6. **汇总裁定**。五席意见按共识与分歧两栏重排，分歧处给仲裁理由；**对抗席的每条关键质疑逐条裁定为成立、部分成立或不成立**，再给整体决定等级与修订路线。

**取长补短的证据**：`ars-academic-paper-reviewer` 的配置卡先行、五席独立、裁定环节最强，但它多席顺序执行、本身不产生新的证据判断；`aris-kill-argument` 的两百字拒稿 memo 是压低自我欺骗的最快手段，但它只做对抗不给严重度；`arf-review-paper` 给更细的分节问题定位；`scientific-critical-thinking` 给证据分级与偏倚风险的定级尺。本 SOP 取第一者的席位结构与裁定＋第二者的 memo 格式＋第四者的定级，并保留一条诚实声明：**同一会话顺序执行不得称为独立评审团**。

### 2.3 受邀审稿：正式意见撰写（review.report）

**触发**：写审稿意见、受邀审稿、推荐等级怎么给、保密评语。
**输入**：待审稿件（含补充材料与图表）；期刊评审表与评分口径；被邀审稿信与编辑提醒。**产出**：`referee-report.md`＋`review-checklist.md`（十二项终检）。

1. **摘要判断**。只读标题、摘要、图表与结论，先写一句「这篇稿子做了什么、值不值得发」并给初步推荐（接收／小修／大修／拒稿重投／拒稿）。**先写下来再读正文**，避免被写作质量牵着走。
2. **逐节取证**。方法看设计与执行（纳排、随机化、盲法、样本量依据、统计方法、软件版本）；结果看报告完整性与一致性（与图表数字对得上、有误差棒、有阴性结果）；讨论看是否越界解释。
3. **报告规范核对**。随机试验对 CONSORT、观察性研究对 STROBE、系统综述对 PRISMA、动物实验对 ARRIVE、病例报告对 CARE；缺哪条列哪条，不写「报告不规范」。
4. **定推荐等级**。从五档里选一档，并用两句话写清「为什么是这一档而不是相邻档」；大修必须说明**哪些问题修不了就该拒**。
5. **主要与次要问题分级**。主要问题逐条编号，每条四要素：问题、为何重要、具体怎么做、是否发表必需；次要问题给位置与建议。两类分开编号，不混排。
6. **保密评语与终检**。给编辑写保密评语（总体判断、对该刊读者的价值、伦理或数据疑虑、是否愿意复审），再跑十二项终检逐条打勾。

**取长补短的证据**：`peer-review` 的七阶段流程、四要素与十二项终检是最完整的正式意见骨架；`nature-reviewer` 给意义与效度两轴的质疑话术与分节红旗；`scientific-critical-thinking` 给报告规范与偏倚风险的具体条目。本 SOP 取第一者的流程与终检＋第二者的分节红旗＋第三者的定级，并执行一条源技能只部分覆盖的规则：**推荐等级与问题清单必须自洽**——列了三条致命缺陷却给小修，编辑会直接退回重写。

### 2.4 证据与数字核验：主张对原始结果（review.audit）

**触发**：核对数据、验证论文数字、主张审查、数字对不上、图像重复检测、复现检查。
**输入**：论文正文与图表；原始结果文件（json／csv／jsonl／指标导出）；代码仓库与运行环境记录（可选）。**产出**：`claim-audit.md`＋`integrity-notes.md`。

1. **建主张清单**。从摘要、结果、图表题注与讨论抽出全部可核主张：每个具体数字、每处优于／高于／显著的比较、每条范围性表述（首个、唯一、普遍），一条一行并标出处行号。
2. **零上下文核验**。**新开会话**，只喂论文与原始结果文件，不喂实验日志、进展报告或作者解释；逐条判通过／存疑／失败，并给原始文件路径与字段名。
3. **统计报告审查**。核样本量与独立单位、效应量与不确定区间、检验前提、多重比较校正、缺失数据处理、事后更改的分析。**指出缺陷即可，不重跑分析**（重算交 stats 域并写明交接内容）。
4. **图像与一致性取证**。图像做重复、拼接、亮度异常检查；表格做加和、百分比反算、样本量前后一致性检查；统计量做整数一致性核对。结果分**阻断／警告／无新问题**三档。
5. **代码与数据可复现**。检查可运行脚本、依赖版本、随机种子、数据可得性声明与运行命令；按说明走一遍能否复现主表，不能复现的标出缺哪一步。
6. **核验表与结论**。出表：主张原文、出处、原始来源、判定、差异说明、建议改法；表后三句总结——几条失败、几条存疑、对结论强度的影响。

**取长补短的证据**：`aris-paper-claim-audit` 的零上下文与「逐条对原始文件」是防被叙事带偏的关键机制，但它只做数字核验；`aris-integrity-forensics` 给确定性取证（图像重复、整数一致性）与三档分级；`nature-statistics` 给统计报告审查的清单（以独立实验单位为 n、区分技术重复）。本 SOP 取第一者的零上下文纪律＋第二者的取证＋第三者的统计清单，并明确一条红线：**取证命中一律写「需作者解释」，不得直接定性为造假**——图像压缩与通道合并都会造成伪命中，误判的代价远比漏报高。

### 2.5 修回策略：大修与小修的应对路径（review.revise）

**触发**：修回策略、大修怎么改、审稿意见太多先改哪条、改稿范围控制、返修时间不够。
**输入**：编辑决定信与全部意见原文；当前稿件与上一版；期刊对返修的要求（期限、标红方式、字数上限、是否逐条回复）。**产出**：`revision-plan.md`＋`consistency-check.md`。

1. **定决定类型**。从编辑信摘出决定类型、返修期限、必须回应的条目编号与编辑的特别指令，把这些原文抄进计划开头。**不得按意见条数或语气反推决定类型**——「意见很多」不等于大修。
2. **逐条分诊**。每条一行：编号、审稿人、意见摘要、类别（关键／主要可行／次要易改）、优先级、涉及章节、预计字数影响、计划动作（改稿／补分析／说明／部分接受）。
3. **处理冲突与重叠**。两人以上提同一问题合并处理并在信里说明重叠；两位审稿人要求互相矛盾时**点名冲突**，按编辑优先级取舍并写理由；确实做不到的写原因与最接近的替代方案。**禁止两边都口头答应、改稿只做一边。**
4. **排改稿优先级**。按「动摇结论的改动 → 补分析与补数据 → 结构性重写 → 表述与格式」排顺序，每个动作绑定具体意见编号，并标依赖关系（先补的分析做完才能改讨论）。
5. **控范围与字数**。列范围表：必改项、可留项（写理由）、不新增项；核算净字数变化对期刊上限的影响，超限列裁剪项。
6. **一致性复核**。标红稿、干净稿、回复信三者对齐：信里说改了的每一处，标红稿必须有对应改动且位置正确；标红处数量与信中描述一致；干净稿不含批注与修订痕迹。**抽查不少于十条。**

**取长补短的证据**：`scholar-respond` 给决定类型提取、分诊仪表盘、冲突处理与范围控制，作者侧最完整；`nature-response` 给模式路由、互盲审稿人的隐私过滤与包件一致性审计；`aris-rebuttal` 给问题编号与原子化改稿计划。本 SOP 取第一者的分诊与冲突规则＋第二者的一致性审计＋第三者的改稿计划，把「决定类型只能来自编辑信」写成硬门——它是这一卡最容易被模型做错的一件事。

### 2.6 逐条回复信撰写（review.rebuttal）

**触发**：写回复信、逐条回复、返修信、承诺怎么说、回复信字数超了、rebuttal。
**输入**：审稿意见原文（含编号与审稿人标识）；修改后稿件与改动位置清单；字数上限、格式要求与允许提交的材料。**产出**：`response-letter.md`＋`paste-ready.txt`（标字符数）＋`commitment-table.md`。

1. **归一化意见**。把每份意见拆成原子条目并编号（R1-C1、R2-C3），每条保留原文逐字引用。编辑意见单列一套编号（E.1、E.2），不得与审稿人条目混编。
2. **过三道硬门**。**覆盖率门**：条目数与状态表逐一对应；**来源门**：每个事实标到论文原文／审稿意见／用户确认的实验结果／未来工作；**承诺门**：每个承诺标「已完成／已批准可写／仅未来工作」三态之一。
3. **配策略与语气**。每条先归型（误解／证据不足／新颖性／基线公平性／范围／表达／理论／效率／其他），再按审稿人心智类型选姿态：澄清、补证据、缩范围、承认并解释、给最近替代。
4. **逐条四段**。意见原文、我们的理解、修改内容、修改位置四段。位置必须到页、行、图或表号；**无法照办时给理由与替代方案**，并说明在正文哪里承认了该局限。
5. **过七项检查**。覆盖完整、来源可核、承诺一致、语气无攻击与谄媚、编号与正文引用一致、字数不超、条目内只谈这一件事。
6. **裁字数定稿**。先算字符数（含标题与编号），超限按「冗余表述 → 客套话 → 开场段 → 措辞压缩」的顺序裁，保留四段结构与位置信息；定稿出可粘贴文本并标注实际字符数。

**取长补短的证据**：`aris-rebuttal` 的三道硬门、原子化编号与字数预算最严格；`scholar-respond` 的四段式与语气模板最可直接用；`rebuttal-guidance` 给「按审稿人心智类型选策略」的判断层，解决「同样是反驳，为什么有的被接受有的激怒审稿人」；`nature-response` 给隐私过滤与模式路由。本 SOP 取第一者的门禁＋第二者的结构＋第三者的策略，并保留一条本域特有的话术纪律：**不空谢、不辩解**——「谢谢您的宝贵意见」与「您误解了」都属同类噪声，一个是空话，一个是引战。

### 2.7 申诉与被拒后的转投策略（review.appeal）

**触发**：申诉怎么写、被拒了怎么办、转投策略、改投哪家、拒稿重投、转投信。
**输入**：拒稿决定信与全部意见；稿件与被拒版本；目标期刊与备选清单；编辑沟通记录（可选）。**产出**：`appeal-or-resubmit-plan.md`＋`resubmit-cover-letter.md`＋`lessons-learned.md`。

1. **判拒稿类型**。四类：编辑直接拒、外审后拒、附修改邀请的拒、返修超期被拒。**每类的默认动作不同**，先写清类型再谈对策。
2. **根因诊断**。归到七类：范围不匹配、贡献门槛、方法致命缺陷、框架不匹配、理论薄弱、写作质量、数据与可复现性；每类给对应修法与时间成本（1～2 周、2～4 周、1～3 月）。
3. **决定申诉还是转投**。**只有存在明确程序性错误**（审稿人明显误读且结论依赖该误读、利益冲突未披露、流程违规）时才考虑申诉；否则转投。申诉信只讲事实与错误，不重述研究价值。
4. **改框不改分析**。保留数据与分析，改开篇钩子、贡献声明、理论侧重与章节顺序以匹配新刊读者；列对照表：新增、删除、改写各几段，**分析部分零改动**。
5. **转投信与目标选择**。按子领域列期刊阶梯并标范围与门槛差异；转投信必须**披露曾在别处评审**、列主要修改、声明未一稿多投，核对字数与格式。
6. **经验日志**。一页日志：原刊与决定、根因、审稿人反复提的主题、这次改了什么、没改什么及理由、新目标刊、框架差异与预先防御的质疑点。

**取长补短的证据**：`scholar-respond` 的四型 triage、七类根因、期刊阶梯、改框规则与转投信模板几乎覆盖全流程；`nature-response` 提供编辑沟通的模式路由与包件一致性；`aris-rebuttal` 给申诉中的证据组织方式。本 SOP 取第一者的主干，并加两条源技能只隐含的硬规则：**禁止一稿多投，一次只有一个在审**、**申诉默认不启动**（没有点名具体错误就转投）。

### 2.8 审稿质量自查：自己的意见能不能执行（review.selfcheck）

**触发**：审稿意见自查、意见是否可执行、审稿越界了吗、推荐与意见一致吗、双盲泄露。
**输入**：已写好的审稿意见或自审报告；目标刊评审表与审稿人行为准则；稿件原文（核对位置）。**产出**：`selfcheck-table.md`＋`review-final.md`。

1. **可执行性逐条检查**。逐条问「作者看到这句知道要做什么吗」：能说出改哪、补什么、改到什么程度才算合格；说不出的改写成具体动作，仍说不出的删掉。
2. **证据化改写**。每条补位置与依据：节段行图号＋原文引句或表内数字；找不到依据的条目**降级为待核**，不得以断言形式留在正式意见里。
3. **越界与偏好检查**。逐条区分领域标准要求与个人偏好：标准类保留为主要问题，偏好类降为建议并注明非必需；要求补新实验的条目单独列出，说明是否发表必需。
4. **一致性复核**。推荐等级与主要问题清单对照：列了三条致命缺陷却给小修、只提文字问题却给拒稿，都要改。
5. **身份与保密检查**。检查自我引用式暴露、特定实验室才有的表述、对作者身份的猜测；保密信息只写在给编辑的栏位，公开意见不含未发表数据与他人稿件内容。
6. **出终检表**。六项做成表格逐项打勾，未通过项写明改法并回原文修改；交出去前再删一遍情绪化与绝对化表达。

**取长补短的证据**：`peer-review` 的十二项终检是机械可查的底稿；`paper-audit` 要求每条发现锚定已核引文（`quote_verified`），正好治「无依据的断言」；`nature-reviewer` 给匿名与保密的检查点；`arf-review-paper-light` 的越界检查（至多五条必做分析、越界知识标待确认）给了一个可操作的量化上限。本 SOP 取四者各一层，把「可执行」定义成句子级判据：**能说出改哪、补什么、改到什么程度**——三样说不全就是不通过。

## 三、常见错误清单

1. **写无法执行的评语**。「创新性不足」「论述不充分」「建议加强」——作者无法据此行动；改写成「第 3 页第 2 段：主张 A 只有单次实验支撑，建议补三次重复或把措辞降为「初步观察到」」。
2. **四件套缺一还照发**。位置、问题、依据、建议少一项，这条意见在结论里就不算数。
3. **依据靠印象**。依据必须是原文引句或表内数字；找不到就写「未能定位」并标待核。
4. **拿个人偏好当领域标准**。偏好降为建议并注明非必需；把偏好列为主要问题是审稿越界的典型形态。
5. **要求补全新实验**。先判是否发表必需；非必需一律降为建议，并说明为什么不是必需。
6. **按意见条数推决定类型**。「意见很多」不等于大修；决定类型只能来自编辑信原文。
7. **推荐等级与问题清单打架**。三条致命缺陷配小修，编辑会退回重写。
8. **让作者「文中已写明」被打回**。读者没看懂就是表述问题；应承认表述不清并指出原文位置、改写该段。
9. **回复信漏条或合并后失联**。回复条数必须等于意见条数（含编辑意见），编号一一对应。
10. **承诺含糊**。每个承诺必须标「已完成／已批准可写／仅未来工作」；没做的不能写成已做。
11. **审稿人之间互相矛盾时两边都答应**。点名冲突、按编辑优先级取舍、写明理由。
12. **第二轮引入新分析**。范围蔓延是返修被拒第一原因；新增内容会引出没被审过的新质疑。
13. **把取证命中直接说成造假**。只能写「需作者解释」并分阻断／警告两档。
14. **用描述性一致性替代原始数据**。没有原始文件就只能标「无法核验」，不能判通过。
15. **申诉当情绪出口**。只有具体程序或事实错误才申诉；范围与门槛问题靠改框转投。
16. **一稿多投或转投不披露**。一次只投一家；转投信必须写明曾在别处评审及主要修改。
17. **声称独立评审团**。同一会话顺序执行的席面必须注明执行方式，不得冒充多模型独立评审。
18. **泄露身份或保密信息**。自我引用、实验室特有说法、未发表数据写进公开意见，都属违规。
19. **报告写得漂亮但数字对不上**。核验永远在前；修辞不能替代证据。
20. **隐去统计缺陷只谈写作**。统计缺陷要指出（不重算），并在报告里给该重算什么、交谁算。

## 四、交付前自检

| # | 检查项 | 判据 |
|---|---|---|
| 1 | 四件套 | 每条质疑都有位置（节／段／行／图／表）、问题、依据（原文引句或表内数字）、建议，缺项不计入结论 |
| 2 | 可执行 | 每条都能说出「改哪、补什么、改到什么程度」；说不全的已改写或删除 |
| 3 | 三问覆盖 | 「数据支不支持结论／新在哪／读者能否读懂并复现」逐项有作答，且落到具体段落或图表 |
| 4 | 分级 | CRITICAL／MAJOR／MINOR 分栏统计，Critical 命中即判不通过并标阻断项 |
| 5 | 推荐自洽 | 推荐等级与问题清单一致；不一致处已改并留理由 |
| 6 | 越界 | 要求补实验的条目逐条说明发表必需性；偏好类已降为建议并注明非必需 |
| 7 | 报告规范 | 按研究类型核过 CONSORT／STROBE／PRISMA／ARRIVE／CARE，缺项逐条列出 |
| 8 | 核验表 | 每条主张有出处与原始来源；判通过必附原始文件依据；判失败必给论文值与原始值 |
| 9 | 取证措辞 | 命中项一律「需作者解释」＋阻断／警告分档，无造假定性 |
| 10 | 决定类型 | 有编辑信原文依据，不是从条数或语气推断 |
| 11 | 覆盖 | 回复条数＝意见条数（含编辑意见），编号一一对应无缺无重 |
| 12 | 承诺 | 每个承诺标已完成／已批准可写／仅未来工作；无虚假承诺 |
| 13 | 位置 | 回复信每条都到页／行／图／表号 |
| 14 | 字数 | 字符数实测不超上限；超限按冗余→客套→开场→措辞顺序裁并复校覆盖 |
| 15 | 包件一致 | 标红稿、干净稿、回复信三者逐条对应，抽查不少于十条 |
| 16 | 范围 | 第二轮及以后无未被要求的新分析、新引用、新论证；净字数变化已核对 |
| 17 | 申诉门槛 | 仅在点名具体程序或事实错误时启动申诉，否则默认转投 |
| 18 | 转投合规 | 转投信披露前次评审与主要修改，声明未一稿多投 |
| 19 | 语气 | 无指责、无空谢、无讽刺、无「显然」「众所周知」式断言 |
| 20 | 身份与保密 | 无自我引用式暴露、无实验室特有说法、无对作者身份的猜测；保密内容只在给编辑栏位 |
| 21 | 诚实声明 | 顺序执行的席面已注明执行方式，未声称独立评审团 |
| 22 | 无编造 | 无编造的文献、数值、行号、图号、审稿人证词、期刊流程与录用偏好 |
