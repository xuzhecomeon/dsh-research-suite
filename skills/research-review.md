# 从投稿到修回：自审、审稿、修回与回复信

本域只有两种失败模式。**第一种是把判断写成结论**——「整体创新性不足」「方法有缺陷」「写作需改进」，这些话作者拿不到任何可执行动作，编辑也看不出你的依据在哪里。**第二种是把没有证据的回应写成证据**——为了显得有理而堆不相关的数据，为了显得配合而承诺做不完的实验，最后在下一轮被逐条翻出来。

两条铁律贯穿全篇：

1. **证据化**：每条质疑四件套——位置、问题、依据、修改建议。缺一件就不是意见，是情绪。
2. **不编造**：影响因子、审稿周期、接收率、实验数字、页码行号，一律不写；需要时写占位或「未核实」。

## 一、本域边界

1. **做**：投稿前的主编视角自审；审稿人视角的深度质疑（含最强反驳）；受邀审稿时的正式报告与保密评语；证据与数字核验（主张对原始文件、统计缺陷、代码可复现）；修回策略与分诊；逐条回复信；被拒后的申诉与转投；给自己审稿意见做质量自查。
2. **不做**：不做语言润色与降 AI 味（转 polish）；不重新跑统计分析、不重算效应量（转 stats，本域只指出缺陷并要求作者补报）；不代写成稿章节（转 writing）；不做投稿信以外的宣传材料（转 writing）。
3. **不做但要说清**：不预测接收概率与审稿周期（无可靠依据，任何数字都是编造）；不替用户决定申诉还是转投（给代价与两条路，决定权在作者）。
4. **边界争议**：用户说「帮我改到能被接收」时，拆成两段：可执行的修回与回复（本域），与语言与排版打磨（polish）。两段并行但交付物不同，不要混在一份文件里。
5. **必须停下问人**：目标期刊的评审表、字数上限、提交形态（单文档或逐审稿人分开）、决定类型（小修/大修/不明确）——这四项拿不到就不许开始写回复信。

四处真实冲突，按下面规则取舍：

- **审稿人视角要不要全信**：五席面板与八路报告都会给出大量意见，但作者的时间有限。取舍是**按阻断性排序，只保留能改变结论的**；其余降为次要或进保密评语。
- **证据核验要不要重算统计**：核验只对账不重算。取舍是**能说清分析单位的就判，说不清的进存疑**，绝不代跑统计。
- **修回要不要全改**：不是。取舍是**能改的改、不能改的给理由与替代**，且两者都要有明确位置或明确拒绝理由。
- **申诉还是转投**：取舍是**只在程序或事实错误时申诉**，其余一律转投；申诉信不写「我们不同意判断」。

## 三、融合协议

### 3.1 投稿前自审（review.presubmit）

1. **定范式与目标期刊**。先判稿子属于技术、人文、实证社科、金融经济还是法学范式，再核它是否落在目标刊范围与体裁内；范式或目标刊不清就先问，不许拿错尺子量。判据：说不出「读者是谁、本刊近半年发过同类文吗、篇幅合规吗」三问，就还没资格打分。
2. **主编视角三道筛**。用主编第一小时会看的三处过筛：摘要有没有一句说清做了什么、引言有没有把缺口立住、结论有没有对应证据；同时标出秒拒硬伤（超页数、格式不符、宣称与证据错位）。命中硬伤则先改硬伤，质量项暂缓。
3. **分节扫红旗**。按摘要、引言、方法、结果、讨论、图表逐节找红旗：方法缺样本量依据与判定标准、结果缺对照与误差定义、讨论把相关写成因果、图表误差棒未定义、引文编号对不上。每条写清位置、问题、依据。
4. **机械项一次过**。可脚本化的项一次过完：页数字数、参考文献格式、图表与公式编号连续性、术语与标点一致、占位符与待办残留、补充材料清单是否与正文对齐。机械项与判断项必须分开标注来源。
5. **定严重度与闸门**。分致命、重大、次要三档：影响结论成立性的为致命，影响可信度与可复现的为重大，只影响阅读的为次要；闸门只由致命项决定。同一问题在两档之间犹豫时按下限判并注明理由。
6. **出必改清单与结论**。交付三段：计数摘要加最该先改的三条、按严重度排序的发现表、一句结论（可投／修后投／换刊）。结论必须由计数推出；致命项未清零时不得写「修后投」。

### 3.2 审稿人视角深度质疑（review.referee）

1. **定配置卡**。通读一遍定四件事：主学科与次学科、范式与方法类型、目标刊层级、成稿成熟度；据此写三到四张「谁以什么立场审」的配置卡，先给用户确认再开审。配置写错，后面五席全是错的尺子。
2. **分节扫红旗**。按摘要、引言、方法、结果、讨论、图表、伦理七处逐节记红旗与位置；方法处重点查样本量、随机化与盲法、分析单位、排除规则，结果处重点查对照、误差、阴性结果与选择性报告。
3. **写最强反驳**。先不看其他意见，用二百词写一篇单一连贯的拒稿备忘，只挑最致命的一条论证链，说清哪一步没被证据撑住；再拆成三到七个原子点，逐点判现有文本是否已答。**不许因为「作者是故意这么设的」就自动免检**。
4. **五席独立质疑**。按配置卡分五席（主编角度、方法、领域、跨学科视角、魔鬼代言人）各自先写完再汇总；各席不得互看，否则会向第一个结论收敛。
5. **汇总裁定**。按严重度合并去重，标出共识项与争议项；每条致命质疑必须显式裁定（采纳／不采纳及理由），再给决定倾向与不可随意变更的改稿清单。未裁定的致命质疑不许静默放过。
6. **出质疑件**。两份交付：给人读的质疑报告（一句总判断加按阻断性排序的质疑，每条四件套），与给机器用的清单（位置、类型、严重度、对应三问）；末尾附作者最可能回击的三点及回应思路。

### 3.3 审稿意见撰写（review.report）

1. **通读并写摘要判断**。先通读不查细节，只用两三句回答：它想解决什么、结论是什么、证据是否撑得住、是否适合本刊。这段是编辑最先读的部分，必须给结论而不是过程。
2. **逐节取证**。按七处逐节走，每节记证据与判断；核心是两条：方法上的样本量依据与判定标准，结果上的对照、误差定义与阴性结果完整性。每条都要能被翻到具体那一页那一句。
3. **定推荐等级**。在拒稿、大修、小修、接受四档里选一档，并用已列问题反推：有阻断性缺陷必是大修或拒稿，只有表述与格式问题才是小修。列出重大意见却推荐小修是最伤信誉的失误。
4. **写分级正式意见**。分重大与次要两级：重大按逻辑排序编号，每条写「问题／为何严重／怎么改／是否发表必需」；次要给位置与建议即可。**要区分「我认为更好的做法」与「必须改的缺陷」**——把偏好写成必须改，会让作者做无谓实验。
5. **写保密评语**。只放三类：不宜公开的怀疑（如疑似重复发表、图像异常）、整体判断、公开意见里不便展开的取舍理由；不放情绪与人身评价，也不写超出自己证据能力的话——拿不准写「建议编辑部核查」。
6. **终检自查**。交稿前逐条过十二项：意见是否都有位置、重大项是否有改法、推荐是否与问题一致、是否越界要求额外实验、是否泄露身份、语气是否可读。核心就一句：如果你是作者，看到这条知道下一步做什么吗。

### 3.4 证据与数字核验（review.audit）

1. **建主张清单**。把摘要、正文、图注里所有可核查的主张与数字抽成表：一句主张、出处位置、涉及数字、依赖的图表或结果文件；定性表述也要抽并标待核。**以句为单位而不是以段为单位**——夸大常发生在后半句。
2. **对原始文件**。逐行对账：数字、单位、样本量、比较对象、条件设置各对一次；对不上就记原文值、文件值与差异，**不就地修正原文**，也不替作者圆「大概是四舍五入」。
3. **判通过或存疑**。每行给判定：通过（对得上）、存疑（口径不明或缺文件）、不通过（数值或结论与证据冲突）。不通过必须附原文句与正确值，存疑必须写清缺哪份材料。无法判定一律进存疑，绝不猜。
4. **统计报告审查**。对每个统计结论问三件事：测了什么、分析单位是什么、推断到哪一层。最常见硬伤是把细胞、视野、技术重复当独立样本，n 被放大数倍；这一步不需要重算，只需要作者说清分析单位与每单位样本量。
5. **代码与可复现**。按清单核依赖与环境声明、数据与模型获取路径、随机种子、运行入口，以及**论文描述与代码默认值是否一致**——最常出「悄悄话」的地方。发现不一致只陈述差异，不断言作者作弊。
6. **出核验表**。交付三块：核验范围与边界（核了什么、没核什么、为何）、逐条结果表（主张／文件／判定／差异／建议）、需作者补充清单。边界必须写在最前，否则读者会把「未核」当「已核通过」。

### 3.5 修回策略（review.revise）

1. **定决定类型**。从编辑信取出决定类型（小修／大修／修改后再审／评审后转投／不明确）与编辑指令编号；定不下来就问，**不许从意见条数或语气反推**。类型决定整包策略：把大修当小修处理，下一轮会暴露同样的缺陷。
2. **原子化与分诊**。把意见拆成一人一条的原子项并编号，逐条标类别（致命／可行重大／易改次要）、优先级、涉及章节、字数影响、计划动作；汇总出总条数、各级计数、跨审稿人重叠项。**分诊看板必须在动笔前给用户看**，因为改稿预算是有限的。
3. **排优先级与冲突**。排序规则：编辑点名最高、两人以上提出的必须完整处理、低成本可完成的先做；冲突的要求点明冲突并给取舍理由，不可行的要求给最接近的替代方案。同时满足相反要求是自欺。
4. **建改稿计划**。每条修改一行：意见编号、改哪一节哪一段、改成什么、状态（已改／计划改／不打算改）；另附超范围日志，写明哪些意见不触发改稿及一行理由。交稿前用这张表反查，无孤儿修改。
5. **定范围与字数**。按上限算预算，改动分三类：必须进正文的、可移入补充材料的、只能文字回应的；正文优先替换与压缩，不为回应而无限追加。字数超限被退的代价远高于少写两段。
6. **复核一致性**。跑两层：答复完整性（每条有回应、无遗漏、无未批准承诺）与包一致性（标红稿、干净稿、回复信的位置与引文对得上）。**每次再改都要重跑**，因为回复信里引用的是改后原文。

### 3.6 逐条回复信（review.rebuttal）

1. **归一化意见**。逐字存好编辑信与各审稿人意见，编成 E.1、R1.1 这样的编号；先确认字数或字符上限与提交形态。**上限决定回答粒度**，写到一半才发现超限，被迫压缩的往往是关键证据。
2. **定策略与语气**。逐条认意见类型（误解、证据缺口、新颖性、基线公平性、范围声称、表达、理论、效率），据此定回答结构与语气；再定两到四个全局主题，把共享关切集中解一次，避免同一条关切在三个回复里各答一半。
3. **定结构**。按骨架写：抬头与轮次、两句最重要改动、分审稿人分节（每节先引意见原文再答）、编辑意见单列、改动汇总表、结尾署名；互盲时每位审稿人各一份，不得互相引用。
4. **逐条写四件套**。每条按「意见原文／我们的理解／我们的回应／改了什么及位置」写四块；能改的给页行图，不能改的给理由与替代。证据用最少但最直接的量——**堆砌无关结果会稀释关键指标**。
5. **过八道门禁**。逐条核：覆盖、来源、承诺、语气（无攻击无谄媚无回避）、一致、字数、单份可读、设计选择披露。最易漏的是设计选择披露：审稿人若发现结果来自未说明的子集，整段回复会被当不诚实。
6. **定稿与字数**。出两版：精确字符数的粘贴版与带格式的富文本版；超限按「冗余→客套→开场→措辞」压缩，**任何情况下不删对关键关切的直接回答**；压缩后逐条复核。

### 3.7 申诉与转投（review.appeal）

1. **判拒稿类型**。按编辑信判四型：编辑直接拒、评审后拒、拒但附改后重投邀请、修改后再审过期。直接拒通常指范围或体量不匹配，原刊重投几乎不会成功；判断依据必须是编辑信原句，不能凭意见严厉程度推测。
2. **查根因**。归到七类：范围错配、贡献不够、方法缺陷、框架不符、理论太薄、写作质量、数据可复现；每类给修法与大致周期，选唯一一条主根因。**把方法缺陷当写作问题处理，转投后会在新刊遇到同样质疑**。
3. **定申诉或转投**。只有能指出程序错误或事实错误（读错数据、漏看材料、程序违规）才考虑申诉；否则转投。申诉信只谈这两类错误，不谈「我们不同意判断」。
4. **转投改框**。分析不变、框架变：按目标刊读者重写开篇钩子、贡献声明、引文侧重、章节顺序与字数。原样转投是被拒第二次的最常见原因，编辑一眼能看出这是别家退下来的稿子。
5. **写转投信**。写明曾在他处评审、据此做了哪些主要修改、未同时投往他处，再给一段针对本刊读者的价值说明与字数合规确认。**声明评审史不是减分项，隐瞒才是致命的**。
6. **留经验日志**。写一页日志：原刊与决定、主根因、反复出现的审稿主题、改了什么与没改什么及理由、新目标刊、框架差异、下一轮要预先防御的点。同一批意见常跨刊复现，答不上同样的质疑说明根因没修。

### 3.8 审稿质量自查（review.selfcheck）

1. **逐条可执行性**。每条意见单独读，问三件：作者知道改哪里吗、知道改成什么样吗、知道为什么吗。三问答不上就重写；最低标准是「换一个人拿着这条意见也能动手」。
2. **证据化改写**。每条挂一个原文位置或图表编号；找不到位置的，降级进保密评语或删掉。判断型意见要写依据，不能只说「不合适」——能定位的意见即使被反驳也推进讨论。
3. **查越界与偏好**。逐条问：这是必需的还是我偏好的做法？要求额外实验时写明为何是发表必需；只是另一种做法则改为建议并说明不构成阻断。判据是「不做这一步结论是否就不成立」。
4. **查一致性与推荐**。核三处一致：推荐等级与问题数量、公开意见与保密评语、各条意见之间是否自相矛盾。一边说方法有致命缺陷、一边推荐小修，编辑只会上报为不可靠审稿。
5. **查身份与保密**。扫有无泄露身份的信息（自引、内部项目名、特定机构表述）与不该进公开意见的保密内容；双盲场景下任何可识别线索都要去掉。身份泄露常常不是故意的，一句「我们项目里遇到过」就够了。
6. **出自查表**。输出自查表：每条的位置、可执行性判定、是否越界、来源与置信度、需改写处；改完后终稿与表一并留档。意见一旦提交无法修改，这张表是唯一能说明当时判断依据的东西。

## 四、判据与红线

### 4.1 决策判据（若…则…否则…）

- **范围先于质量**：若目标期刊未定或明显不匹配，则先做范围匹配三问；否则不进入打分与必改清单。
- **只跑需要的模式**：若问题只在格式、页数、编号这类机械项，则只跑机械清单；否则进入判断项自审。混在一起会让作者抓错重点。
- **无联网不补齐引文**：若怀疑漏引但无法核实，则标「未核实待补」并给检索式；否则不许写具体文献。
- **致命项阻塞结论**：若致命项未清零，则结论只能是「修后投」或「换刊」；否则可判「可投」。
- **拒稿备忘只一条**：若目标是找最可能被拒的那一处，则只跑拒稿备忘与逐点裁决；否则才跑完整多席面板。
- **配置冲突先对齐**：若配置卡与用户预期冲突（例如按顶刊标准审一篇投稿给普通刊的稿），则先对齐配置再开审；否则按错层级判死可修的稿。
- **越界判断先声明**：若领域超出自己判断能力，则只审能负责的部分并在评语中声明边界；否则不该给整体推荐。
- **疑似不端只进保密评语**：若发现疑似学术不端迹象，则写进保密评语并请编辑部核查，公开意见只谈科学；否则不许在公开意见里直接指控。
- **无原始文件不判可信**：若拿不到原始结果文件，则只核内部一致性与可复现声明并写明边界；否则不许说「数字已核对」。
- **报告不全不要求重算**：若统计缺陷只是报告不全，则要求补报效应量与不确定区间；否则才要求重做分析。
- **决定类型须有出处**：若决定类型定不下来，则先问用户或从编辑信找原句；否则不许开始写回复信。
- **冲突按编辑优先级取舍**：若两位审稿人要求相反，则点明冲突并按编辑优先级取舍并解释；否则两边各改一半会让双方都不满意。
- **超限先删冗余**：若回复信超上限，则按「冗余→客套→开场→措辞」压缩并保每条关键回答；否则不许删难答的条目。
- **只有程序或事实错误才申诉**：若只有判断分歧，则转投；否则才写申诉信。
- **改框不改数据**：若转投，则重写框架与叙事、数据与结论不动；否则就是在新刊重复同一个故事。

### 4.2 可机械检查的 gates

**证据化（每域通用）**

1. 每条质疑含位置、问题、依据、修改建议四件套，缺项不计入。
2. 无「整体创新性不足」「写作需改进」「建议修改」这类无落点评语。
3. 三问各有具体段落或图表落点：数据支持结论吗、相比已有工作新在哪、目标读者能读懂并复现吗。
4. 每条意见都能被作者翻到对应原文位置（页／行／段／图／表）。

**一致性与闸门**

5. 推荐等级与所列问题数量一致：有重大项时不得推荐小修。
6. 公开意见与保密评语不矛盾，保密评语不含人身评价。
7. 每条修改都绑定意见编号与具体位置，无悬空项与孤儿修改。
8. 回复信条数等于审稿意见条数，无漏答也无虚构意见。
9. 承诺项均标注已完成或计划中，无未批准承诺。
10. 字数与格式在期刊上限内，提交形态符合要求（单文档或逐审稿人分开）。

**禁编造**

11. 全文无编造数字：影响因子、审稿周期、接收率、实验数值、页码行号。
12. 核验类交付写明核验范围与未核部分，无推断性补数。

### 4.3 红线（命中即退回，不解释）

- 在评语里写无法执行的话（「创新性不足」「不够严谨」而无位置与依据）。
- 用「文中已写」回应审稿人——审稿人没看到就是表述问题，必须改稿。
- 在自己没有证据的领域下结论性判断。
- 编造实验、数字、引用、页码行号、期刊数据。
- 把个人偏好写成必须改的缺陷。
- 回复信里承诺未经批准的实验或分析。
- 一稿多投，或在转投信里隐瞒曾在他处评审。
- 用摘要的说法代替原始数据核验，然后宣称「已核对」。

## 五、模板与校验

### 5.1 审稿三问落点表

每条核心质疑必须落到三问之一，并给出落点：

| 三问 | 追问什么 | 必填的落点 | 不合格的写法 |
|---|---|---|---|
| 这个结论的数据支持得住吗 | 分析单位、对照、误差、效应量、阴性结果 | 具体图表或段落＋缺失的证据类型 | 「证据不足」 |
| 和已有工作相比新在哪 | 最近三篇的最接近工作与差异轴 | 文献名或「未能给出候选对比」＋差异轴 | 「创新性不够」 |
| 按目标期刊读者能读懂并复现吗 | 方法可复现性、术语、结构与篇幅 | 具体缺失的复现要素（参数、数据、代码、流程） | 「写作需改进」 |

### 5.2 证据化四件套（每条意见的格式）

```
[位置] 第 3.2 节第 2 段 / 图 4 / 表 2 第 3 列
[问题] 一句话说清读者会卡在哪：<…>
[依据] 原文引文「…」或缺失要素清单：<…>
[建议] 具体可执行的改法（补什么、改什么、删什么），并标严重度：致命／重大／次要
```

### 5.3 修回分诊看板

| # | 审稿人 | 意见摘要 | 类别 | 优先级 | 涉及章节 | 字数影响 | 计划动作 |
|---|---|---|---|---|---|---|---|
| R1.1 | R1 | <一句> | 致命／可行重大／易改次要 | ★★★ | 方法 2.3 | +180 | 补样本量依据并改文 |

汇总行必填：总条数、各级计数、净字数变化、当前与预计字数对上限、跨审稿人重叠项（最先修）、冲突要求与拟解决法、不可行要求与最近替代、编辑点名项、后续轮新增意见单列。

### 5.4 审稿意见模板（含推荐意见与保密评语）

```
一、摘要判断（两句）
本文报告了……，其结论依赖……。总体判断：<可发表／需重大修改／不适合本刊>。

二、推荐意见（四档选一）
拒稿 / 大修 / 小修 / 接受
一句话理由：<由下列重大意见的条数与性质推出>

三、重大意见（按逻辑排序，每条四件套）
M1. [位置] … [问题] … [依据] … [建议] …（是否发表必需：是）
M2. …

四、次要意见
m1. [位置] … [建议] …
m2. …

五、给作者的问题（可选）
Q1. …

六、给编辑的保密评语（不公开）
- 整体判断与推荐理由（与公开意见一致）
- 不宜公开的怀疑：<如疑似图像重复、疑似重复发表>（措辞：建议编辑部核查）
- 声明边界：本评语只覆盖<…>部分
```

写法要点：推荐信（cover letter）与审稿报告是两件不同的事——推荐信是作者写给编辑的，审稿报告是审稿人写给编辑的，不要混。审稿报告里的推荐必须与重大意见数量一致；不一致时改推荐，不改意见。

### 5.5 逐条回复信模板（含无法照办时的措辞）

```
致 <编辑名> 与各位审稿人：
感谢……（一句）。以下逐条回应，修改处已在正文标红，改动位置以「页/行」标注。

【对编辑意见】
E.1 意见原文：「……」
回应：……（做了什么）
修改：第 X 页第 Y 段（附改后原文）。

【对审稿人 1】
R1.1 意见原文：「……」
我们的理解：……
回应：……
修改：第 X 页第 Y 段 / 图 3（附改后原文）。

……

【改动汇总】
| 章节 | 主要改动 | 对应意见 | 字数变化 |
|---|---|---|---|
```

五套措辞（按事实选，不按心情选）：

| 情形 | 措辞骨架 |
|---|---|
| 完全同意 | 感谢指出。我们同意……现已改为……（附改后原文与位置）。 |
| 部分同意 | 我们同意其中关于……的部分并已修改；但对……我们维持原做法，理由有两点：……（引证据）。为避免误解，已在第 X 页明确说明。 |
| 礼貌不同意 | 谢谢这一提问。我们保留原处理，因为……；若改为审稿人建议的做法，会引入……问题。我们已在第 X 页补充说明该选择。 |
| 无法照办 | 我们认同这一关切的重要性。受<数据获取/伦理限制/设备条件>限制，本轮无法完成该项；已改为……（最接近的替代），并在讨论部分明确写出该局限（第 X 页）。 |
| 审稿人误解 | 这是我们的表述不够清楚。实际做法是……；已在第 X 页改写为……（附改后原文）。 |

### 5.6 转投信与申诉信要点

**转投信**必含四块：曾在何处评审及据此做了哪些修改（逐条，**不得省略评审史**）、与目标刊读者和范围的契合点、未同时投往他处、字数与格式合规确认。

**申诉信**（仅程序或事实错误时写）必含三块：具体错误点与原文证据、该错误对决定的影响、请求（重新送审／换审稿人／编辑复核）。**不写「我们不同意审稿人判断」**。

### 5.7 审稿自查表（交稿前逐项打勾）

| # | 检查项 | 通过判据 |
|---|---|---|
| 1 | 每条意见有位置 | 能指到页／行／段／图／表 |
| 2 | 重大意见有改法 | 每条都写了「怎么改」而不只是「哪里错」 |
| 3 | 无空话评语 | 全文检索不到「创新性不足」「写作需改进」这类无落点句 |
| 4 | 推荐与问题一致 | 重大项 ≥1 时推荐不是小修 |
| 5 | 无越界要求 | 每个额外实验都写了为何是发表必需 |
| 6 | 公开与保密一致 | 两处判断不矛盾 |
| 7 | 无身份泄露 | 无双引、内部项目名、可识别机构表述 |
| 8 | 语气可读 | 无讽刺、人身评价、情绪化措辞 |
| 9 | 统计口径说清 | 分析单位与 n 已判或已要求作者补 |
| 10 | 伦理与合规 | 涉及人与动物时已核批号与同意方式 |
| 11 | 引文可核 | 所有点名文献可被作者定位（无则标未核实） |
| 12 | 边界声明 | 超出能力的部分已声明或未评 |

### 5.8 校验

- 包内结构自检：`node scripts/verify-capabilities.mjs review`，须 0 错误。
- 文档自检：七节标题齐全且顺序不变；每条 gates 能被人工在五分钟内判定；无「可参考某某技能」式空话。
- 交付前机械核查（可脚本化）：回复信条数 vs 意见条数、每条是否含位置字段、是否出现禁用词（创新性不足／建议修改／文中已写）、字数是否超上限。
- 占位规范：未定信息统一写成【期刊名】【字数上限】【决定类型】这类全角方括号占位，并在交付物末尾附「待用户补全」表。

## 六、交付物

| 交付物 | 文件名约定 | 格式要点 |
|---|---|---|
| 自审报告 | `自审报告.md` + `必改清单.csv` | 计数摘要＋Top3＋按严重度排序的发现表＋一句结论 |
| 质疑报告 | `质疑报告.md` + `质疑清单.csv` | 总判断＋按阻断性排序＋每条四件套＋作者最可能回击三点 |
| 审稿报告 | `审稿报告.md` + `保密评语.txt` | 摘要判断／推荐／重大／次要／保密评语；推荐与问题数一致 |
| 核验表 | `核验表.csv` + `证据审计报告.md` | 范围边界在最前；逐条判定＋差异＋可粘贴建议 |
| 修回包 | `分诊表.csv` + `改稿计划.md` + `冲突与不可行清单.md` | 每条意见有状态；无孤儿修改；字数预算可见 |
| 回复信 | `回复信.md` + `逐条映射表.csv` + `粘贴用纯文本.txt` | 分审稿人分节＋改动汇总表；字符数精确 |
| 转投或申诉 | `转投方案.md` + `转投信草稿.md` / `申诉信草稿.md` + `经验日志.md` | 根因唯一；转投声明评审史；申诉只谈程序或事实错误 |
| 审稿自查 | `审稿意见自查表.md` | 十二项逐条通过情况＋需改写处 |

统一要求：中文全角标点；术语首次出现给英文；每份交付物首段写「本文件覆盖什么、还缺什么」；末尾列待补项。
