# 科研任务总入口（dsh-research-suite v2）

这套件不是一堆技巧的合集，而是**一套执行规程**：把数百个科研技能按"能干什么"归并成能力卡，卡里写清每个技能的擅长与短板、彼此在哪些点上互相补足，再给一条**融合协议**——照那 7 步做完，就是该能力的合格产出。

## 一、第一步永远是选能力，不是选技能

收到科研诉求后，先调：

```
research_playbook(task = 用户原话)
```

- `task` **尽量贴用户原话**（「帮我把这篇讨论去 AI 味，字数别变」比「润色」匹配得准）。
- 有明确倾向时加 `domain`（writing／polish／figures／stats／literature／format／ideation／review／slides）。
- 返回 1～3 张能力卡：id、标签、融合协议、分歧点、判据与红线、交付物、成员账本。

**禁止的行为**：不要先宣布「我将使用 XX 技能」，也不要说「首选某技能」。技能名在本套件里是实现细节；对外只讲能力与流程。用户不需要知道背后调了 `paper-deweight` 还是 `humanizer-zh`。

## 二、选完能力后照协议执行

融合协议是**有序步骤**，每步都标了来源技能、做法与细则（含阈值）。要求：

1. **按序执行，不跳步**。跳步等于放弃该步负责的质量维度。
2. **分歧点按条件选**。卡里的「分歧点」写的是「当 X → 用 A 而不是 B，因为 Y」，不是建议，是判据。
3. **判据与红线交付前逐条核**。这些是可机械检查的（字数守恒、EPV、SMD、DPI、标点），核不过不算完成。
4. 需要原文细节时用 `research_kb_read`，**最多读 2 个**技能全文——协议已经浓缩过，读太多反而淹没。

## 三、九个能力域

| 域 | 覆盖 | 典型诉求 |
| --- | --- | --- |
| writing | 中文／英文论文、综述、标书、报告 | 写一篇、补方法学、按范文改结构 |
| polish | 去 AI 味、语体回正、英文润色、字数守恒改写 | 这段太像 AI、帮我改得像人写的 |
| figures | 数据图、机制图、示意图、配色与版式 | 画生存曲线、画机制图、图太丑 |
| stats | 研究设计、R 执行、预测模型、PSM、生存、MR、Meta | 跑个多因素、做倾向评分、审一下统计 |
| literature | 检索式、数据库、精读、查证、参考文献格式 | 找文献、这篇讲了什么、核 DOI |
| format | 期刊格式、GB/T 7714、三线表、投稿材料 | 转成目标期刊格式、排参考文献 |
| ideation | 选题、假设、基金标书逻辑、创新点包装 | 想个题、这个本子怎么立 |
| review | 投稿前自审、模拟审稿、回复信 | 帮我挑毛病、写 response |
| slides | 组会／答辩／会议幻灯、备注讲稿 | 做个汇报 PPT、这页怎么讲 |

## 四、工具面（7 个只读工具）

- `research_playbook` — 原话 → 能力卡 + 融合协议（**入口**）
- `research_capability` — 展开某张卡，或列某域全部能力
- `research_catalog` — 在数百个原始技能里检索（找「还有没有别的做法」）
- `research_kb_read` — 读技能原文／索引，支持分段
- `research_standard` — 读内置规范（期刊格式、参考文献、统计报告、图件、幻灯）
- `research_gate` — 门禁：数据六道闸门、交付自检、互斥对、禁止事项、硬规则、交接物；传 `text` 可对交付文本做机械检查
- `research_suite_status` — 装载自检

## 五、六条铁律（任何域都适用）

1. **全角标点**：中文语境的逗号、句号、括号、书名号、引号一律全角。
2. **引用编号上标**，按出现顺序编号；参考文献按 GB/T 7714-2015 著录，逐篇真实可查，**严禁编造**。
3. **统计一律用 R 跑**（Rscript），Python 只做抽取、文档、绘图、排版。
4. **机制图四要素**：分子通路、受累器官、实验动物与操作、胞内外信号分层；**不标参考文献编号**，证据分级用实线／虚线图例。
5. **交付物形态**：文字 `.docx`（不给 `.md`）；表格三线表；图件 ≥300 DPI 且留可编辑源文件。
6. **禁 AI 套话与绝对化**：值得注意的是、综上所述、众所周知、首次、唯一、完全、彻底——删或改。

## 六、收尾

- 交付前调 `research_gate`（可带 `section: all` 与 `text`）。
- 涉及统计的，先过 `section: data` 的六道闸门再写任何数字。
- 交付时说明：用了哪张能力卡、过了哪些闸门、留下了什么可复现材料（脚本、数据、sessionInfo）。

## 七、边界

- **不做**：与本套件域无关的纯编程／运维／闲聊任务；不代替临床判断；不生成用于投稿的伪造图像或数据。
- **患者数据不外发**：个体数据、影像、病历截图只在本机处理，不使用任何需要上传的外部服务。
- 用户指定了范文或目标期刊时，**以用户指定为准**，本套件的默认写法退居其次。
