# 论文写作域融合 SOP（research-writing）

本 SOP 面向一件事：**把已有的研究事实写成能投、能被审稿人按体例逐条核对的文字**。它不生产研究事实，只负责把事实组织成合格的文稿；凡是事实层面的缺口（缺数据、缺引文、缺统计），一律回上游补，不在写作层用文字填。

## 一、本域边界

1. **接什么**：已有研究材料（研究设计、数据表、结果、图表、病例资料、文献清单）→ 文字成品；已有稿件 → 按目标体例回改。两类输入都要求先有「事实清单」，没有事实清单的委托先走 §3.11 蓝图。
2. **统计不自己算**：RR／OR／HR、95%CI、P 值、I²、AUC 等一律引用 stats 域结论；写作域只负责「把数字放对位置、给对精度、配对句式」。同一份数据在写作域重算一次，就会出现正文与表格数字不一致，这是审稿人最先抓的硬伤。
3. **检索不自己编**：文献检索策略、查新、数据库选择转 literature 域；本域只做引文落位、编号、著录格式与真实性核验。没有原文只有文献表时，真实性只能标「待核实」，不得宣称已核实。
4. **不做同行评审**：稿件质量打分、拒稿建议、审稿意见撰写转 review 域。本域可以执行「拒稿八因倒查」这类自检，但自检通过不等于评审通过。
5. **交付形态边界**：文字类成果默认交 .docx，不交 .md；.md 仅作中间工作稿与自查记录。LaTeX 工程按项目内既有工具链走，输出 .tex 与编译产物，不擅自把 .tex 转 Word。
6. **范围硬边界**：不替作者改研究设计，不补做实验，不生成不存在的数据、标识符、伦理号与文献条目；用户指定范文时，范文的章节层级与风格优先级高于本 SOP 的任何默认值。

## 三、融合协议

每一步都带阈值或判断标准；未达阈值不进入下一步。步骤里的数字来自目标期刊或学校文件时，以文件为准并在交付说明里写明取用哪一档。

### 3.1 中文医学论著 IMRaD 分节（writing.zh-med-imrad）

1. **定类型与字数配额**：论著正文 ≤8000 字、中文摘要 250～500 字、参考文献 15～25 条；综述 ≤6000 字、25～30 条；病例报告 ≤2000 字。配额先写进蓝图，无配额不开写。
2. **证据与图表先行**：证据台账逐条标 L0～L4（L0 原始数据、L1 随机对照或系统综述、L2 队列、L3 病例或横断面、L4 无来源）；L4 数量必须为 0。图表先定表 1 基线、表 2 主要结局、图 1 筛选或生存曲线。统计量只引用 stats 域输出。
3. **引言三段**：第一段疾病负担与临床问题；第二段现有研究缺陷 ≥2 条、每条带引文；第三段本研究目的与设计一句话。每段 150～250 字，全节引文 15～25 条。缺陷写法固定为「已有研究做了 X，但样本小／单中心／未分层，故仍需 Y」。
4. **方法四段**：研究对象（纳排标准、样本量依据）、干预或暴露、结局指标、统计方法（软件与版本、检验方法、检验水准）。他人按此段能独立复现，否则返工。
5. **结果只述不评**：按基线、主要结局、次要结局、安全性排序。每句必带统计量（x̄±s 或 M(P25,P75)、n(%)、t 或 χ² 值、P 值与 95%CI）。出现「导致」「说明」「提示」「证明」即返工该句。
6. **讨论三段**：首段 ≤150 字回扣目的并给「是／否／部分」的回答；中段与既往研究比较（8～15 条引文，给同类样本量）；末段局限性 ≥3 条（样本、设计、测量、随访、混杂各一条）加结论 ≤3 句。
7. **交付前五轮自查**：硬性规则扫描、投稿版式、反例清单、语言深度、文献真实性，逐轮出「通过／返工」，五轮全通过才交 .docx。

### 3.2 中文学术语体基准与去口语化（writing.zh-med-voice）

1. **立语体指纹**：取目标刊近三年同栏目范文 2～3 篇，抽平均句长、每段句数、第一人称次数、被动句比例、每千字连接词密度。句长可接受带为范文均值上下 20%，第一人称目标值为 0。用户指定范文时以范文为准，未指定时对中华医学会系列期刊。
2. **主语回正**：「我们」「笔者」「本文作者认为」替换为「本文」「本研究」「本组」「专家组」；无施事主语句改被动或补实体主语。替换后逐句确认责任主体不丢失。
3. **缩略语首现**：首次出现写「中文全称（英文全称, ABBR）」，英文全称小写、缩写大写，例「劳力型热射病（exertional heat stroke, EHS）」。全文只定义一次；同一概念出现两种译名即返工统一。
4. **句长与衔接**：单句 ≤40 字，一句一意。删「首先／其次／最后／此外」机械序列，改「因此／然而／与之相反／在此基础上」承接。段内序数衔接词 ≥3 个即判机械并列，改并列复句。段落 150～300 字，主题句在首句。
5. **去 AI 腔与绝对化**：删空副词（非常／极其／十分）、抬价动词、伪洞见开场；「根本性／决定性／首次」降为「显著／重要」或补引文。命中处记「位置＋类型＋原文摘录（≤30 字）」，无数据支撑的最高级直接删。
6. **三轮复核**：结构→语言→排版。排版核全角标点、首行缩进 2 字符、标题字号层级。复核四问：是否新增事实、是否丢失限定、强度是否抬高、能否直接投稿。

### 3.3 英文 SCI 论文写作与期刊适配（writing.en-sci）

1. **定 venue**：优先级为显式 venue > 期刊 allowlist > 明确领域 > 中性基线。据结果定节标题、摘要形态、字数上限。无 venue 信号时用中性基线并标注缺失信号。
2. **时态与语态分层**：方法与观察结果过去时；公认事实与图表描述现在时；本研究主张现在时。方法段被动为主，贡献陈述主动。同一段时态跳变不超过两次。
3. **hedging 分级**：确证结果用 show／demonstrate；相关用 associate with；推测用 may／suggest。禁用 prove／guarantee／confirm。强度上限等于证据等级：观察性研究不写 reduced，只写 associated with。
4. **结构式摘要**：Objective／Methods／Results／Conclusions 四段，150～250 词，结果段 ≥3 个数值并带 CI 或 P 值，结论段不新增信息与缩写。
5. **引文与版式终检**：正文引文与参考文献双向对齐，缺号与孤立条目为 0；引文 ≥3 条必做独立核验（DOI 能否解析）；改写只动语言，引用键、交叉引用、数字、缩略语逐项等同原文。

### 3.4 综述与 Meta 分析的报告写作（writing.review）

1. **定类型**：叙述性、系统、Meta 三型。系统与 Meta 必须有检索式、纳排标准、PRISMA 流程图；叙述性必须声明检索范围与时限。文献只有十余篇时按叙述性写。
2. **主题簇与空白**：文献聚成 3～5 簇，每簇 ≥3 篇代表文献并做簇末比较。研究空白 ≥3 条，每条写成「已有研究在 X 上一致，但在 Y 上证据不足或结论冲突」。
3. **逐段五步**：主题句→文献支持→综合分析→批判评价→过渡。同段引文 ≤8 条，超则拆段。禁止「某某认为…某某认为…」逐篇罗列；观点归并到主题，多个同结论研究合写一句带多引文。
4. **结论与展望**：给主要发现、空白、方向、意义四项。展望含对象、设计、终点三要素；不写「建议开展多中心研究」式空话。
5. **报告清单**：系统综述对 PRISMA 2020 逐条勾选；Meta 加异质性与发表偏倚（漏斗图或 Egger 检验）；证据质量用 GRADE 分级并进结果呈现。流程图三段数字与正文一致。

### 3.5 病例报告（CARE）与短篇通讯（writing.case-report）

1. **准入判断**：一句话测试——该病例能否改变读者的诊疗决策（罕见表现、新诊断、新治疗反应、重要不良反应）？答否即改投他型。单例不宣称疗效因果。
2. **去标识与伦理**：按 18 类标识逐项清除（姓名、日期、住院号、联系方式、可识别影像特征等）；年龄写区间、日期写相对时间（入院后第 X 天）；给书面知情同意声明。
3. **按 CARE 成文**：标题含病例报告字样与关注点；正文顺序为患者信息、临床发现、时间线、诊断评估、治疗干预、随访结局、讨论、患者视角（可选）；摘要 150～250 字，关键词 3～5 个。
4. **讨论只谈可迁移经验**：同类病例比较 ≥3 篇并列作者、年份、表现、治疗、结局；机制句用 may／suggest／「可能」；局限 ≥3 条（单例、随访短、不能推因果）。
5. **短篇与 Letter 改版**：压缩到 800～1200 字，标题 ≤15 词，引文 ≤10 条，图表 ≤2 个，不设摘要与关键词；同意与利益冲突声明保留。
6. **投稿包齐备**：投稿信按背景、贡献、适配、声明、结尾五段，逐句可追溯到稿件证据；附 CARE 清单勾选表。信中不得出现稿件没有的数字。

### 3.6 学位论文与开题报告（writing.thesis）

1. **定学位层级与规范**：先识别模板（thuthesis／pkuthss／generic）与学位层级，取学校格式清单；无清单按 GB/T 7713 执行并记录依据。硕士常见下限 3 万字、博士 5 万字，以学校文件为准。
2. **章级蓝图**：绪论、文献综述、方法、结果、讨论、结论六章，配额参考 15%／20%／25%／25%／15%。每章一个主判断，章首引出、章末回扣。
3. **绪论漏斗**：五层收窄后落到研究空白与本文任务；绪论引文 20～40 条，近五年占比 ≥50%；不写「填补国内空白」；研究流程图放在研究内容与方法之间。
4. **方法与结果可复现**：方法按输入对象、预处理、模型或干预、训练或实施、输出、与实验对应六段；结果按假设顺序给图表，不解释。每个关键模块映射到消融实验或局限说明。
5. **结论与创新点**：三段式——首段总领、编号列贡献且每条对应一章、末段展望具体。贡献动词须有证据（提出／构建／验证／揭示），不加「国际领先」。
6. **盲审版与终检**：盲审版隐匿作者、导师、致谢、基金与可识别自引；只写副本为盲审版，原文件不动；终检项含页码、目录、公式编号、参考文献格式。评阅意见按台账法逐条回复并标修改位置。

### 3.7 摘要与关键词（writing.abstract-keywords）

1. **定格式与字数**：期刊论著用结构式四要素，中文 250～500 字、英文 150～250 词；病例报告 150～250 字；综述 200～400 字；学位论文摘要 800～1000 字并单列创新点。目标刊有明确要求时以其为准并记录档位。
2. **四要素素材**：目的句写问题与设计；方法句写对象、干预或暴露、结局、统计方法（含样本量与设计类型）；结果句 ≥3 个统计量并带 CI 或 P 值；结论句 ≤2 句、不新增信息。
3. **中文摘要体例**：用【目的】【方法】【结果】【结论】方括号结构词，第三人称，无文献引用，缩写首现给全称，结果数字带单位。
4. **英文摘要**：Objective／Methods／Results／Conclusions，结构词加粗；方法过去时、结论现在时；不直译中文句式，不用 Firstly／Moreover 堆叠衔接。
5. **关键词**：3～8 个，中文分号分隔、末尾不加标点；尽量对上 MeSH 主题词并给英文对照；不重复标题词；每个关键词都要能在摘要中找到对应概念。
6. **中英一致性核对**：逐要素对照数字、结论强度、缩写；摘要出现正文没有的数据即返工；摘要结论强度不得高于讨论。

### 3.8 图表题注与正文呼应（writing.figure-table）

1. **定图表清单**：每项写一句「它回答什么问题」，答不出即删。一图一表只回答一个问题，同一数据不在表与图中重复；每 1000 字 ≤1 表 1 图。
2. **选表还是选图**：精确数值、多变量、需逐项比较用表；趋势、分布、相关、流程用图。生存数据用 Kaplan-Meier，筛选流程用 CONSORT／PRISMA 图。
3. **写题注**：表题在表上方、图题在图下方；题注含对象、指标、时间、统计方法缩写，不写结论性判断；缩写与 n 值来源写进注释；题注与正文连续 15 字以上雷同即返工。
4. **正文呼应**：每张图表出现在正文首次提及之后；正文给一句解读并只强调一到两个关键差异，不整段复述数字；图表按首次提及顺序编号。
5. **排版规范**：三线表仅三条横线，表内小数点对齐、单位入表头；图不低于 300 DPI、字号不小于 6 pt；学位论文用章.序编号（如图 3-1）。
6. **机械核对**：编号连续、正文引用覆盖率 100%、无孤立图表；LaTeX 工程跑交叉引用检查，Word 稿用交叉引用字段核对。

### 3.9 讨论、局限性与结论边界（writing.discussion-limits）

1. **首段回扣目的**：≤150 字，只写主要终点，不堆数字，明确回答引言问题（是／否／部分）。首段出现机制解释即挪到第二段。
2. **与既往比较**：按一致、不一致、补充三类组织，引文 8～15 条，每条给同类研究样本量与结论；不一致处给解释假设（人群、剂量、随访、测量）。禁用「与文献报道一致」而无引文。
3. **机制解释**：只用 may／suggest／「可能」「提示」；每个假说后接「本研究证据只能提示…不能证明…」；跨物种外推明示；机制段不超过讨论篇幅的三分之一。
4. **写局限性**：样本、设计、测量、随访、混杂五维各一条，共 3～6 条；每条写成「由于…，本研究结论在…范围内成立」；给偏倚方向（高估或低估）。
5. **收结论**：≤3 句，动词按证据选（提示／支持／表明）；不写「首次」「根治」「优于」除非有对照与统计支持；与摘要结论强度一致。
6. **校准**：逐句标强度等级（证明／关联／可能），高于证据的降一级；降级只改情态不动数据；改动记入说明表。

### 3.10 引文编号与 GB/T 7714 参考文献（writing.citation-format）

1. **定体例**：中文刊用 GB/T 7714-2015 顺序编码制（正文方括号上标 [1]、[1-3]、[1,3-5]）；英文刊按刊要求用 Vancouver／AMA；全文统一，不混用。
2. **建文献台账**：每条录 DOI、PMID、题名、作者、年卷期页与来源；无 DOI 记来源与查证日期；台账与正文编号双向映射，同一文献只占一个编号。
3. **正文编号**：按首次出现顺序编号并全部上标，置于句末标点之前；上标数等于引用出现数；删句后重编全篇编号，不做局部补丁。
4. **条目著录**：「作者. 题名[J]. 刊名, 年, 卷(期): 起-止页. DOI: 10.xxxx/xxxxx.」；作者超三人英文取前 3 加 et al.、中文取前 3 加等；英文刊名用 NLM 缩写、中文全称；类型标识置题名后；字段缺失数为 0。
5. **真实性核验**：引文 ≥3 条或投稿前必做独立核验，逐条查 DOI 或 PubMed；状态三档为已核实、待核实（须标注）、无法核实（删除或换文献）。核验不在写稿同一上下文完成。
6. **双向对齐**：出对齐表（编号、首现位置、条目首作者、核验状态）；缺号或孤立条目即返工；LaTeX 工程先校验 .bib 再核交叉引用。

### 3.11 选题收敛与成稿蓝图（writing.outline-blueprint）

1. **定位范式**：用方法而非学科名判（实验建模=STEM、文本档案=人文、问卷回归=社科、整合已有研究=综述）；同时定全文或单节、草稿或终稿。终稿模式不允许占位符（表格除外）。
2. **六问收敛**：论文类型、学科、题目、背景与目的、方法、章节结构。题目 ≤20 字并含研究对象加方法或结局；背景与目的各两句话。六问答不全不进入蓝图。
3. **建证据台账**：每条主张挂 L0～L4；无来源主张换两三个关键词检索，仍无则删句或改写。台账与蓝图同步维护。
4. **排章节蓝图**：每节写角色、主判断、证据编号、字数配额、缺口五列；贡献 3～4 条各映射一节；模块与挑战一一对应。
5. **五项对齐自检**：案例是否复现、局限对挑战、目标对贡献 1、挑战对模块、贡献对章节；任一失败回蓝图重排，不在正文里绕。
6. **交付蓝图**：.docx 蓝图含题目、摘要草稿、章节表、证据台账、缺口清单；标明哪些节可直接写、哪些待补材料；用户确认后再进入逐节写作。

## 四、判据与红线

**铁律（违反即返工，不接受「下一版再改」）**

1. **范文优先**：若用户给出范文，则按其章节层级、标题措辞、篇幅与风格模仿；否则对标中华医学会系列期刊。若两者冲突，以范文为准并在交付说明记录差异。
2. **中文语境全角标点**：若正文出现半角逗号、句号、括号、直引号，则计为错误并逐处替换；代码块、公式、DOI、英文文献条目内部除外。交付前跑脚本计数，必须为 0。
3. **引用上标＋GB/T 7714-2015＋真实可查**：若正文引用编号未上标或格式非国标，则返工编号层；若文献无法查到 DOI 或来源，则标「待核实」或删除，绝不保留占位条目。编造文献是本域的一票否决项。
4. **交付 .docx**：若用户要的是可投稿/可提交的成品，则交 .docx；.md 只作中间稿与自查记录。若用户明确要 .tex，则交工程与编译产物。
5. **禁绝对化与 AI 套话**：「值得注意的是」「综上所述」「显著提升」「为…提供了新思路」「具有重要理论意义和临床价值」等一律删除或改写为带具体内容的句子；「根本性」「决定性」「首次」降级或补引文。
6. **统计数字引用 stats 域**：若写作域出现新算出的统计量，则视为越界，回 stats 域重算并回填；写作域只引用、不派生。

**若…则…否则（decide 展开）**

- 若用户先要提纲，则用章节蓝图（节-角色-主判断-证据编号）先行；否则直接成文会结构返工。
- 若研究是诊断准确性或预后模型，则先对 STARD／TRIPOD 清单；否则通用 IMRaD 会漏必报条目。
- 若稿件是第一人称叙事（部分病例报告），则保留少量第一人称并注明期刊允许；否则全篇硬改会破坏叙述连贯。
- 若用户要「更有文采」，则只清 AI 腔与绝对化、保作者声音；否则加修辞会触发「不专业」判断。
- 若稿件是中文初稿要投英文刊，则先抽中文事实骨架再按目标刊体例译写；否则逐句直译会把中式语序带进英文。
- 若用户只说「润色英文」，则走保守路线只改语言；否则无授权的重写会改掉主张与术语体系。
- 若文献只有十余篇且无可复现检索，则按叙述性综述写并声明检索范围；否则强行套 PRISMA 会被判伪系统综述。
- 若需合并效应量，则转 stats 域计算、本域只负责表述；否则手算无法在文字层补救。
- 若病例仅一例且随访不足三个月，则写短篇或 Letter；否则长文讨论支撑不足。
- 若涉及可识别患者影像，则删除或改示意图；否则打码仍可能被反向识别。
- 若用户给 docx 而非 LaTeX 工程，则按学校规范手工检查并出 Word 修改清单；否则强行迁移模板增加风险。
- 若已收到评阅意见，则用台账逐条回复并标修改位置；否则二次送审仍会被指出。
- 若目标刊要单段摘要，则写单段但保留四要素顺序；否则硬套结构词会被格式退修。
- 若中英摘要只能保一个，则先保英文摘要的语法与时态；否则直译会暴露中式英语。
- 若数据只有三五个数值，则写进正文；否则小表占版面。
- 若期刊限图表总数，则移次要终点去补充材料；否则压缩题注会破坏自明性。
- 若结果为阴性，则写「未观察到差异」并讨论检验效能；否则「有下降趋势」无统计支持。
- 若用户只有文献表没有原文，则只做格式与编号对齐并标待核实；否则默认真实会传播错误引文。
- 若目标刊要 Vancouver，则改方括号非上标并改条目格式；否则会被排版退修。
- 若用户只说「帮我写这篇论文」，则先出蓝图并确认；否则结构返工且证据缺口会被编造内容填补。
- 若材料不足以支撑任何一节，则交缺口清单与最小可写范围；否则凑字数会引入无来源主张。

**机械门（交付前脚本可判）**

- 摘要四要素标记齐全、中文摘要字数落在目标区间；
- 结果节因果/解释动词计数为 0；
- 引用编号连续、上标数等于引用出现数、与文献表条目数一致；
- 每条文献含 DOI 或 PMID（无则标注）；
- 局限性 ≥3 条且每条标明影响的结论；
- overclaim 词（首次／根治／证明／完全）命中数为 0；
- 图表编号连续、正文引用覆盖率 100%；
- 正文半角标点计数为 0。

## 五、模板与校验

### 5.1 交付前检查清单（逐项打勾，缺一项不交）

1. 目标刊/学校体例已确认，字数档位已记录；
2. 全文引用编号按首次出现顺序、全部上标、无跳号；
3. 每条文献 DOI 或 PMID 可查，核验状态已标；
4. 摘要四要素齐全，中英摘要数字与缩写一致；
5. 全文缩略语首现给中文与英文全称；
6. 结果节无解释动词，句子均带统计量；
7. 讨论有局限性段（≥3 条）且结论不越证据；
8. 图表三线表、题注位置正确、正文引用全覆盖；
9. 全文全角标点，无 Markdown 残留（**加粗**、# 标题）；
10. 无「值得注意的是」「综上所述」类套话与绝对化措辞；
11. 伦理号、基金、利益冲突、作者贡献声明齐备；
12. 输出 .docx（或 .tex 工程）且文件名含版本号。

### 5.2 高频替换表

| 原文类型 | 替换为 | 判据 |
| --- | --- | --- |
| 我们／笔者／本文作者认为 | 本文／本研究／本组 | 中文期刊正文第一人称计数应为 0 |
| 值得注意的是／综上所述／换言之 | 直接陈述事实或结论句 | 空转句一律删，不保留过渡 |
| 显著提升／大幅改善 | 降幅／增幅具体数值＋P 值＋95%CI | 无数字即空话 |
| 根本性／决定性／首次 | 显著／重要／（首次须有检索支撑引文） | 绝对化措辞零容忍 |
| 由于样本量小 | 由于样本量有限（n=…），估计精度受限，结论仅在该人群成立 | 局限性须给偏倚方向 |
| 具有显著性差异 | 差异有统计学意义（P=0.03） | 中文统计表述惯例 |
| 与文献报道一致 | 与某某等报告的 X 例结果一致（引文编号） | 无引文不得声称一致 |

### 5.3 可直接跑的校验片段

把成稿导出为纯文本（`稿.txt`）后，在包根或任意目录执行；脚本只读文本，不改稿。

```powershell
# 1) 中文字符数（去掉空白后统计 CJK 字符）
node -e "const t=require('fs').readFileSync('稿.txt','utf8');console.log((t.match(/[\u4e00-\u9fa5]/g)||[]).length)"

# 2) 半角标点计数（正文语境应为 0；代码/DOI 段请先剔除）
node -e "const t=require('fs').readFileSync('稿.txt','utf8');console.log('半角逗号',(t.match(/,/g)||[]).length,'句号',(t.match(/\./g)||[]).length,'括号',(t.match(/[()]/g)||[]).length)"

# 3) 结构式摘要四要素是否齐全
node -e "const t=require('fs').readFileSync('稿.txt','utf8');for(const k of ['【目的】','【方法】','【结果】','【结论】'])console.log(k,t.includes(k)?'OK':'MISSING')"

# 4) 引用上标与编号连续性（导出文本里上标会平铺成 [n]）
node -e "const t=require('fs').readFileSync('稿.txt','utf8');const n=[...t.matchAll(/\[(\d+)\]/g)].map(m=>+m[1]);const uniq=[...new Set(n)].sort((a,b)=>a-b);console.log('引用次数',n.length,'编号数',uniq.length,'最大号',uniq.at(-1),'跳号',uniq.filter((v,i)=>v!==i+1))"

# 5) AI 套话命中清单
node -e "const t=require('fs').readFileSync('稿.txt','utf8');const w=['值得注意的是','综上所述','不容忽视','众所周知','提供了新思路','具有重要意义'];console.log(w.filter(k=>t.includes(k)))"
```

```
三、语体门：第一人称 <0/n>；套话命中 <n>；单句超 40 字占比 <n%>
四、待补项：<缺数据/缺文献/缺伦理号，逐条列出>

```
