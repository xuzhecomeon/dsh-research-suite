# 降重模块三：降低 AIGC 痕迹

> **用途**：加载本模块处理论文的 AIGC（AI 生成内容）检测问题。即使重复率为 0，AI 味过重也会被标红。本模块覆盖**词汇/句式层**与**篇章结构层**两个维度的痕迹，是降 AI 的唯一模块。
> **核心思想**：**结构重组优先于词汇替换，同义词替换无效。** 检测系统识别的不是某个具体词汇，而是文本的统计特征——句式分布、段落结构、逻辑闭环的规整程度。
> **系统差异**：知网较友好；维普更严，需更高频次的句式变动。
> **配套**：正文降重请加载模块一；文献综述请加载模块二。
> **文风约束**：若用户文风与偏好文件已加载（工作区 `文风与写作偏好设定.md` 或 `references/文风与偏好设定.md`），其约束优先级最高；本文与文风文件冲突之处，以文风文件为准。
> **版本**：v2.2

## 〇、三条硬性铁律（指针，唯一权威版本见 SKILL.md）

- 速记：① 保持学术书面语（口语化原文也须回书面语，严禁文言腔，降 AI 不等于口语化）；② 字数变动 ±5% 以内，数据/年份/引用一字不动；③ 自然流畅不生硬。
- 完整定义以 **SKILL.md「三条硬性铁律」** 为唯一权威版本，此处不再重复，避免多处维护漂移。

## 一、为什么同义词替换无效

检测系统认的是**并列结构本身**，不是具体用词：

- 把"第一/第二/第三"改成"其一/其二/其三"**毫无用处**——检测系统认的是并列结构本身
- 把"旨在"换成"用以"、把"首先"换成"起初"——检测系统不受影响
- 必须打散成**非并列的因果或递进叙述**

## 二、词汇/句式层排查：六步排查法

### 第一步：排查「了」字

| 高风险 | 修改方案 |
|--------|----------|
| 研究了 B、提出了 B、体现了 B、表明了 B | 删「了」：研究 B、提出 B |
| a 研究了 b | a 对 b 进行研究 |
| a 发现了 b | a 选择 b 作为研究对象 |

### 第二步：排查「A 的 B 与 C」句式

AIGC 检测头号目标，反复出现时极易触发。

```
高危句式：
"A的B与C" → "文字语言中的语法与修辞"
"A的B与C的D" → "公司的技术与管理"

最致命变体（前加修饰语）：
"在研究中得到了前所未有的研究成果与举世皆惊的研究意义"
```

**修改**：删 B 或 C 之一 / 拆成两句 / 删前缀。

```
改写：研究成果包括……其研究意义则在于……
```

### 第三步：排查形容词前缀的「的」

AI 爱在名词前堆形容词 + 的：

```
人机原文：在南京的浦口区，有一条名为凤滁路的赏樱路线，
在这条干净整洁的路的两侧，每到生机勃勃的春天，总会长出美丽的樱花，
而这些有淡淡的清香的樱花，是一道美丽的风景线……

改写：凤滁路位于南京浦口区，作为当地颇有知名度的一条赏樱路线，
在每个春天都能吸引很多外地游客慕名而来，
而那些散发淡淡清香的樱花，更是彰显其美丽。
```

> 把能省略的「的」全部省略，保留必要的即可。

### 第四步：排查「在 XXX 中」反复出现

单次正常，一段多次即为雷同。

```
人机：在某平台中，用户很多。在另一平台中，用户很多。
修改：就某平台而言……就另一平台而言……
```

> 确保每句有完整主谓宾，别话只说一半。

### 第五步：排查口语化与赘述

**赘述**：一段内连续多句 40~70 字的中等复合句匀速排布、无短句打断，必须打散节奏——去无用形容词前缀，用句号在关键处切出短句。个别必要长复合句可保留，不以固定字数上限阉割。

**口语化**：加指令「不要口语化表述，说人话，请书面用语」。

**句长节奏**：长短句交错，段内最长句与最短句相差 4~5 倍（与模式七、十三条原则6 保持一致）。

### 第六步：句式整体翻面

不是替换词语，是把整句的逻辑骨架翻过来。

```
原文骨架：A 做什么，通过什么，以什么方式，有助于什么的发展

改写骨架：为了实现什么目的，由 A 来采取某些措施，结合什么来完成什么
```

**互逆原则**：如果改法 A 被判定为人机，换 B；B 被判定，换回 A。两种骨架彼此互为「伪装」。

## 三、词汇/句式层：高危句式平行排比

系统逻辑：相邻句句式骨架相同（A干B → C干D）= 人机痕迹。

```
高危模式："带领乡镇""借助环境""推动发展""联动产业"
         "提供帮助""给出建议""提高产能"

修改：A 通过某方式联动产业 → A 借助于某方式完成产业联动
```

**最易出问题**：「研究某某」「分析某某」→ 主动换成「对某某进行研究」「选择某某开展研究」。

> 汉语言等文科写得越工整越容易被误杀——不是写得不好，是太好。

## 四、结构层：七类高频 AI 痕迹模式

### 模式一：序数机械并列（最高频，致命）

**表现**：用"第一…第二…第三…"或"首先…其次…最后…"强行组织逻辑，每点结构完全平行。

**为什么是AI指纹**：AI生成器天然偏好用序数词组织逻辑；人类写作更倾向用内在逻辑词（进而、随后、相比之下、问题在于）推进。

**改写方向**：打散序数结构，用因果或递进关系重组。三段等量齐观的并列改为有主次的评述——最重要的详写，次要的一笔带过，最不重要的可以并入其他段落。

### 模式二：对X而言/对Y而言 对仗结构

**表现**：刻意的形式对称，如"对于投资者而言…对于发行人而言…"。

**改写方向**：打破对称句式，改为主从关系或视角转换。可以先写一方视角，再用"但另一方面临的是另一重压力"过渡，避免工整对仗。两段不必等长。

### 模式三：总结性连接词滥用

**表现**：高频使用"这一…""上述…""综上""由此可见""因此可以得出"做模糊回指和机械推导。

**改写方向**：删除或替换为具体指代。AI喜欢用"这一/上述"做模糊回指，人类更倾向直接点名主语。

### 模式四：旨在/构成/体现为/反映了 制度描述套话

**表现**：典型的AI"说明文"腔调，用抽象判断动词替代具体动作描述。

**改写方向**：把"旨在/体现为/构成"换成具体动作描述。少用抽象名词，多用动词。

### 模式五：英文被动语态+抽象名词化

**表现**：英文段落大量被动语态、抽象名词、完美逻辑闭环，每句都是"主语+exhibited/indicated/reflected+名词"的工整结构。

**改写方向**：彻底重写而非逐句改。回到中文原始意思，用更朴素的英文重新表达，多用主动语态，少用抽象名词，允许句子长短不一。

### 模式六：完美的总分总逻辑闭环

**表现**：每段都遵循"总起句→分点展开→总结升华"的完美结构。

**为什么是AI指纹**：人类写作通常有侧重、有跳跃、有未尽之意，不会每段都形成完美闭环。

**改写方向**：
- 允许某些段落不写总结句
- 允许结论以提问或留白方式收尾
- 把部分"总起"挪到段中或段尾，打破"先总后分"的固定模式
- 段落从**具体事实或案例**切入，判断后置或删除

### 模式七：句长节奏均匀化（重要盲区）

**表现**：几乎每句都是40~70字的中等复合句，读起来"匀速推进"，没有长短起伏。

**为什么是AI指纹**：人类写作天然有节奏——短句制造停顿与强调，长句承载复杂逻辑，长短交替构成呼吸感。检测系统对"句长方差过小"很敏感。

**改写方向**：
1. 在一段里穿插极短句（10字以内）与长复合句
2. 用句号在关键处切断逗号堆叠的长句，形成短句强调
3. 改写后自查：段内最长句与最短句至少相差4~5倍
4. 偶尔以反问句或留白句收尾，天然打破匀速感

## 五、六类补充扫描模式

以下六类在七类高频模式中未明确覆盖，改写时需补查。

### 补充①：递进连词过密

**问题**：一段内出现2个以上"此外""另外""与此同时""不仅如此"。

**排查**：全文搜索这些连词，同一段内≥2个即需改写。

**改写**：用句号断句替代连词，或用因果逻辑自然衔接，不依赖过渡词。

### 补充②：不自然礼貌表达

**问题**："值得注意的是""需要指出的是""应当看到"等表达高频重复，形成"伪谦虚"腔调。

**排查**：全文搜索，出现≥3次即需削减。

**改写**：直接陈述事实，不加前置修饰。

### 补充③：领域术语缺乏变体

**问题**：同一术语在一段内反复出现3次以上而不换近义词。

**排查**：标记每段高频术语，同一段内≥3次即需引入变体。

**改写**：准备术语变体表交替使用。核心术语首次出现用全称，后续可用简称或变体，但不能引起歧义。

### 补充④：引用语境缺失

**问题**：引用文献只列作者年份，不说明其具体发现或方法，像在"堆引用"。

**排查**：检查每条引用后是否有1-2句对该文献核心发现的概述。

**改写**：每条引用后补一句"X学者发现…/X的研究表明…"，说明该文献与本文论点的关系。

### 补充⑤：结论过于乐观

**问题**：结论部分缺乏对研究局限性的真实讨论，或局限性讨论流于形式。

**排查**：检查结论是否有独立的局限性讨论，且具体说明limitation的内容。

**改写**：增加1-2句具体局限性，如"本文以单一案例为研究对象，结论的外部有效性受限""样本量较小，量化分析仅作为描述性验证"。

### 补充⑥：数据描述模板化

**问题**：描述表格数据时反复使用"如表X所示，我们可以发现…""从表X可以看出…"等模板句式。

**排查**：全文搜索"如表""从表""可以看出""可以发现""显示"，统计句式是否雷同。

**改写**：变换数据引入方式。例如把"如表X所示，指标A在P2阶段…"改为"指标A在P2阶段已显著攀升（表X），而…"，数据嵌入因果叙述，不单独成句。

## 六、十三条改写核心原则

### 结构层面

1. **结构重组优先于词汇替换**。检测系统认的是并列结构本身，不是具体用词。必须打散成非并列的因果或递进叙述。

2. **打破对称**。"对于X而言…对于Y而言…"必须改成非对称结构。可以一段长一段短，可以只从一个视角深入。

3. **打破总分总闭环**。不必每段都"总起-分述-总结"。某些段落可以不写总结句，某些结论可以以反问或限定语气收尾。

4. **段落从事实切入，判断后置**。删掉每段开头的判断句（"X的滞后性使其不适合…"），改为从案例事实或数据切入，再引出判断。

5. **段落长度变异**。打破等长模式，混合长短段。同一节内的段落长度应有明显差异。

### 句式层面

6. **控句长节奏**。段内必须有长有短、有松有紧，杜绝清一色的40~70字中等句匀速排布。保证最长句与最短句相差4~5倍。用句号切出短句强调。

7. **少用抽象名词，多用动词**。把"这一交叉强化机制可概括为…"改为"两者就这样互相拖累"。把"体现为成交量下降"改为"成交量掉下来"。

8. **控递进连词密度**。同一段内"此外""另外""与此同时""不仅如此"出现≥2次即需改写。

9. **数据引入句式须变化**。不要每张表都用"如表X所示，可以发现…"，改为数据嵌入因果叙述或括号引用。

### 词汇层面

10. **术语变体准备**。改写前为高频术语准备2-3个变体，同段内交替使用，避免机械重复。

11. **删"值得"类礼貌表达**。"值得注意的是""值得关注的"等表达直接删除，用直陈句替代。

### 内容层面

12. **保留事实和数据**。改写的是句式和结构，不是删减内容。所有数据、年份、事件、文献引用必须原样保留。

13. **结论须含具体局限**。明确写出具体limitation（如"单一案例外部有效性受限""样本量小仅描述性验证"），不做泛泛而谈。

## 七、改写工作流程

```
第一步：全文搜索七类高频模式
  → 搜索"第一/第二/第三/首先/其次/最后" → 标记所有序数列举
  → 搜索"对于/对…而言" → 标记所有对仗结构
  → 搜索"这一/上述/综上/由此可见" → 标记所有总结性连接词
  → 搜索"旨在/构成/体现为/反映了" → 标记所有套话
  → 检查每段是否"总起→分述→总结"闭环
  → 检查句长是否均匀（40-70字区间无短句打断）

第二步：按优先级改写
  → P0：序数列举 + 对仗结构（最高频致命）
  → P1：总分总闭环 + 总结性连接词
  → P2：句长均匀化 + 套话动词
  → P3：六类补充模式查漏

第三步：逐段自查
  → 句长比：最长句:最短句 ≥ 4:1？
  → 段落比：同节内段落长度有无明显差异？
  → 开头：是否从事实/数据切入而非判断句？
  → 结尾：是否有机械总结升华句？删掉是否更自然？
  → 连词：同段"此外/另外"是否≥2个？
  → "值得"：全文是否还有残留？
  → 铁律一：语言是否保持学术书面语（原文口语化也已纠正）？有无文言腔残留？
  → 用户文风硬禁令：破折号解释、引号强调、模糊对比术语、感叹号、空洞总结句是否有残留？
  → 铁律二：改写前后字数差异是否在 ±5% 以内？
  → 铁律三：改写后读起来是否自然流畅、不生硬别扭？

第四步：六类补充模式扫描
  → 递进连词密度
  → 礼貌表达清零
  → 术语变体
  → 引用语境
  → 结论局限
  → 数据描述句式

第五步：逐章复检AIGC检测
  → 每改完一章重新跑检测
  → 确认该章降到目标线以下再进入下一章
```

## 八、给 AI 的完整修改指令

一次性投喂以下指令给 Deepseek、豆包等模型：

```
指令1：严格按照我的修改逻辑来改。漏做任何一条我都不会满意。
       这是一局文本修改游戏，遵守我的规则。

指令2：去掉文本中多余的"了"——"研究了""发现了""明确了"的"了"。
       若有必须保留的"了"，向我说明原因。

指令3：若反复出现"A的B""A的B与C的D"句式，更换语序和表述。
       单次出现可保留。

指令4：每次修改对句式结构大改，不是替换同义词。
       更换逻辑语序骨架。每句至少给两个版本。

指令5：禁止对称句式、排比句式、雷同句式。

指令6：长短句交错，段内最长句与最短句相差 4~5 倍。
       用句号在关键处切出短句强调；不以固定字数上限阉割必要的长复合句。

指令7：禁止"从而实现""因此做到"等学术套话。
       识别套话，给出具体替代表述。

指令8：能简则简，说人话，以通顺为主，不过度口语化。
       长句拆成两到三句。禁止辞藻华丽堆叠。

指令9：逐字逐句修改并解释句意。每段改后整理出来，确保通顺有逻辑。

指令10：原文若偏口语化，必须回到学术书面语，不模仿口语腔。

指令11：改写后字数与原文差异控制在 ±5% 以内，不删内容、不注水。

指令12：改写后必须自然流畅、不生硬别扭，避免翻译腔和欧化句式，
       不能为降重而降重地机械拼凑。
```

### 持续施压

AI 一定会偷懒，每次改完后追加：

> 「你尽力了，但我还是不满意。你可以做得更好。好好自我检查有没有严格按照我的规则来，别让我失望。」

反复 2-3 轮直到输出满意。

## 九、AIGC 痕迹高频特征速查

| 特征 | 触发条件 | 修改 |
|------|----------|------|
| 「了」字 | "研究了""提出了" | 删「了」/ 改为"对…进行…" |
| 「A的B与C」 | 反复出现 | 删一留一 / 拆为两句 |
| 形容词+「的」堆叠 | 名词前大量修饰 | 精简，保留必要的 |
| 「在XXX中」 | 一段内多次 | 改为"就XX而言" / 放句末 |
| 平行排比 | 相邻句骨架相同 | 打散结构，相邻句不同型 |
| 序数机械并列 | "第一/第二/第三""首先/其次" | 打散为因果或递进叙述 |
| 对仗结构 | "对于X而言…对于Y而言…" | 改为主从关系或视角转换 |
| 总分总闭环 | 每段总起→分述→总结 | 去总结句 / 结论留白 / 事实切入 |
| 句长均匀 | 全是40~70字中等句 | 穿插短句，最长最短差4~5倍 |
| 学术套话 | "从而实现""综上所述" | 用具体因果逻辑替换 |
| 口语化 | 口语腔、感叹腔、网络用语 | 回到学术书面语 |
| 文言腔 | 「盖」「然」「亦」「所谓」等仿古句式 | 视为失败输出，整体重写回现代书面语 |
| 破折号解释 | 用「——」引出解释或补充 | 改为括号、逗号或拆句 |
| 引号强调 | 用引号突出普通词语 | 删引号；仅术语首次定义、直接引用保留 |
| 模糊对比术语 | 「背离/收敛/共振/倒挂」非标准术语 | 改为具体描述，如「两组数据变动方向相反」 |
| 感叹号 | 学术正文出现 | 改句号 |
| 空洞总结句 | 段尾重复前文、无新信息 | 删除 |

## 十、与降重的区别

| 维度 | 降重（查重系统） | 降 AI（AIGC 检测） |
|------|-----------------|-------------------|
| 检测什么 | 你的文本和别人有多像 | 你的文本有多像 AI 写的 |
| 核心方法 | 同义词替换 + 句式改换 | 句式变换 + 去人机味 |
| 关键陷阱 | 关键词原地不动 | 句式骨架雷同、排比工整 |
| 按系统分 | 知网/万方扩句友好，维普/格子达缩句友好 | 知网较宽松，维普更严格 |

> 两方面都要处理：重复率靠模块一+二，AI 率靠本模块。
