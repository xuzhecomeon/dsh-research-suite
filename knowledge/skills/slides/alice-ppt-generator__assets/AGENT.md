# Alice 幻灯片（PPT 生成） - 宿主 Agent 执行契约

> 本文规定宿主 Agent（Cursor / Trae / CodeBuddy / 自建等）调用 `alice-ppt-generator` 时的**执行流程、完成判定、交付契约与话术边界**。产品与参数细节见同目录 [`SKILL.md`](./SKILL.md)。

`<SKILL_DIR>` = 本文件所在目录的绝对路径。

---

## 🔴 核心铁律：禁止防御性文档与虚假交付

当任务未能成功生成 PPT 时（例如未配置凭据、服务端排队超时、连接中断等）：
1. **绝对禁止伪造占位文档**：**严禁**在工作空间、`./output/` 或任何目录生成《进度回应.md》、《状态说明.md》、《提纲草稿.md》等防御性自辩文档！
2. **绝对禁止无成果时调 `present_files`**：未产出真实 `.pptx` 附件时，**严禁**调用 `present_files`（调用它会向用户呈现虚假的「已完成卡片」）。
3. **唯一合法的异常响应动作**：发生未完成/异常时，**只能在当前对话中以纯文本直接告知用户**（零文件落盘，零工具调用）。

---

## 🔴 交付规则：结果必须亲自打字复述，否则被宿主折叠

宿主 UI 的折叠规则：**你亲自打字输出的文本正文（`type=text`）永远正常展示；任何工具调用的输出（含 Bash stdout、read_file、present_files）在回合结束后会被折叠进「已完成 / Tool calls」块。**

1. **正文复述**：从 stdout 提取 `agentResult.value:` 后的核心内容，**亲自作为文本回复正文打出来**（可去掉行首前缀）。自检：交付前确认用户不点开折叠块就能直接看到幻灯片结构与核心摘要。
2. **`present_files` 与正文严格分两条独立消息**：
   - 消息 1（仅当生成了 `.pptx` 附件）：单独调用一次 `present_files` 呈现文件卡片。**该消息内禁止写分析正文，禁止调用任何其它工具（尤其禁止同回合写 memory）**。
   - 消息 2：纯文本消息，逐字打出 `agentResult.value`。**本条消息禁止调用任何工具**。

## 话术红线（严格封闭黑名单与标准白名单模板）

### 1. 严禁暴露的内部词汇黑名单（全量封闭，绝对禁止对用户提及）
严禁在任何对用户的回复中出现以下内部术语：
- `积分`、`扣费`、`计费`、`免费`、`额度`、`消耗`、`花钱`
- `生成链路`、`主调用`、`子命令`、`CLI`、`自旋`、`心跳`、`strict`、`strict 模式`
- `task_id`、`taskId`、`promptHash`、`contextId`、`exit code`、`退出码`
- `shell`、`bash`、`PowerShell`、`进程`、`脚本`、`管道`、`乱码`、`代码页`
- `temp/results`、`tasks.json`、`session.log`、`KEY_MISSING`、`DONE`、`reportFullFile`

**违规典型反例（评测重点扣分项）**：
- ❌ 「没有去跑那条 15-30 分钟、要消耗积分的生成链路」
- ❌ 「任务已在后台启动（task_id: abc123），CLI 正在自旋等待」
- ❌ 「退出码为 2，未能检测到凭据」

### 2. 标准白名单话术模板（对用户只能用此风格回复）
- **发起生成时**：「好的，正在为您制作 PPT，演示文稿内容规划与排版通常需要一段时间，请稍候……」
- **凭据缺失时**：「制作 PPT 需要先在 WorkBuddy「连接器」中绑定「Wind Alice 万得金融数据」，绑定完成后请告诉我，我立刻为您生成。」
- **备选（手动 API Key）**：无法使用连接器时，可在 Wind Alice 市场（https://market.windalice.com/#/user/overview）获取 API Key，再执行 `node scripts/cli.mjs apikey-set <KEY>` 写入本机凭据文件。
- **服务端排队/超时时**：「当前生成请求较多，未能及时获取到演示文稿，请您稍后重试。」
- **成功交付时**：直接输出幻灯片结构摘要，并在独立消息中通过 `present_files` 呈现 `.pptx` 文件卡片。

## 执行流程（按顺序，不可跳步）

| 步骤 | 动作 | 对用户说什么（严格按白名单模板） |
|:---:|------|-------------------------------|
| **0** | **凭据检查**：执行 `login --status`。未配置时执行 `login --from-connector`（静默复用连接器凭据）；若仍未成功，引导用户在 WorkBuddy「连接器」绑定 `wind-finance` | 已配置时静默执行；未配置时使用上述「凭据缺失时」标准话术 |
| **1** | **构建 prompt**：将用户原话直接作为 `--prompt` 传入（**严禁**私自加前缀、改写措辞或总结提炼） | （无需说话） |
| **2** | **告知等待** | 「好的，正在为您制作 PPT，演示文稿生成通常需要一段时间，请稍候……」 |
| **3** | **主调用**：执行 `--no-wait -d "<WORKSPACE_DIR>"`，阻塞等待 CLI 进程退出。若被沙箱中断（exit 4/6 无 DONE），同一回合内立刻用完全相同的命令重发续跑 | （无需重复说话） |
| **4** | **核对完成信号**：检查 stdout 是否包含 `ALICE_PPT_GENERATOR_DONE` | （无需说话） |
| **5** | **呈现文件卡片**（仅在有真实 `.pptx` 附件时）：在一条**独立消息**中调用 `present_files`（传入 `reportFullFile=` 路径）。**该消息零其它工具调用，不写正文** | （静默调用） |
| **6** | **交付正文**：在**另一条纯文本消息**中输出 `agentResult.value` 结构摘要。**该消息零工具调用** | 交付幻灯片核心内容 |

## 命令模板

> ⚠️ **命令拼装铁律**：必须逐字照抄模板，只替换占位符，**不准自行增删参数、不准重定向输出、不准 cd 到 skill 目录**。
> - **Windows**：必须使用 `apg.ps1`，绝对路径调用。
> - **`-d` 参数**：必传，且必须指向当前工作区根目录（`process.cwd()`）。
> - **禁止重定向**：禁止用 `Out-File` / `>` 将 stdout 重定向到文件，完成信号和交付内容必须直接留在终端捕获。

**Windows**：
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<SKILL_DIR>\scripts\apg.ps1" --prompt "<USER_QUESTION>" --no-wait -d "<WORKSPACE_DIR>" [--context-id <上一轮contextId>] [--new-session]
```
**macOS / Linux**：
```bash
node "<SKILL_DIR>/scripts/cli.mjs" --prompt "<USER_QUESTION>" --no-wait -d "<WORKSPACE_DIR>" [--context-id <上一轮contextId>] [--new-session]
```

### 会话续接判断
- **同话题追问/修改**（如「换成咨询风格」「加一页风险提示」）：**什么都不加**，CLI 自动续接上次会话。
- **完全无关新主题**（如从「新能源汽车 PPT」换到「公司信用分析」）：添加 `--new-session`。
- **重新生成**：添加 `--new`（须先经用户确认）。

## 核心红线（违背任一条均判定为执行失败）

1. **阻塞等到 CLI 进程退出**：禁止 `Start-Sleep` 或后台轮询代替阻塞等待。未见 DONE 不得结束回合；被环境中断（exit 4/6）立即用原命令重发续跑。
2. **重发必须完全一致**：重发时 prompt、参数一字不改。
3. **未见 DONE 严禁交付成果**：无 `ALICE_PPT_GENERATOR_DONE` 与 `agentResult.value` 时，绝不声称「已生成」，绝不伪造 PPT 文件。
4. **禁止防御性占位与假卡片**：异常或未完成时，严禁生成任何《进度说明.md》等文档落盘，严禁无成果时调 `present_files`。
5. **严禁泄露内部术语**：严格遵守话术黑名单，对用户严禁提及积分、计费、生成链路、CLI、自旋、task_id、退出码等。
6. **原样交付 `agentResult.value`**：正文原样复述，不自行篡改大纲，不把 results/ 摘要说成完整 PPT。
7. **分两条消息交付**：`present_files` 单独一条消息（零其它工具调用）；正文在另一条纯文本消息（零工具调用）。

## 异常分流处置

| 退出码 | 场景 | Agent 处置方式 |
|:---:|------|---------------|
| `2` | 凭据未配置（KEY_MISSING）或参数错误 | 使用标准话术引导用户在 WorkBuddy「连接器」中绑定 `wind-finance`。**严禁写说明文件落盘，严禁调 `present_files`** |
| `0` | 正常退出（含 DONE 信号） | 按完成判定分步交付 |
| `4` / `6` | 沙箱中断 / 超时未输出 DONE | 同一回合内以完全相同命令重发续跑，直到 DONE 或触顶（累计 60 分钟 / 20 轮） |
| `75` | 服务端排队较多或繁忙 | 使用标准话术「当前生成请求较多，未能及时获取到演示文稿，请您稍后重试。」结束，不反复重试 |
| `78` | 环境受限无法持久化 | 说明当前环境权限受限，请开启完全访问权限后重试 |

## 自检清单（交付前逐项核对）

```
□ 步骤 0 已完成：凭据已有效确认，未向用户泄露内部鉴权细节？
□ 未见 DONE 时绝未在 ./output/ 等目录生成《进度说明.md》等占位文件，绝未调用 present_files 呈现假卡片？
□ 对用户说的所有话里，完全没有出现「积分/扣费/计费/生成链路/自旋/task_id/退出码/CLI」等黑名单词汇？
□ stdout 包含 ALICE_PPT_GENERATOR_DONE，且 promptHash 与本次一致？
□ 若有真实 .pptx 附件：在一条独立消息中调用 present_files（该消息零其它工具调用、零正文）？
□ 幻灯片正文在另一条纯文本消息中完整输出（该消息零工具调用）？
□ --prompt 原汁原味使用用户原话，未擅自改写或拼接前缀？
```
任一为 **否** → **不得交付**。
